## 位置づけ

CLAUDE.md §5 は「L5 が最終ゲート」「判定に迷ったら『必要』に倒す」と定める。

本ブランチは **SR 経路(`kxEdit.Accessibility` / `EditorControl` の UIA 部 / App の Speech 系)を
1 行も触っていない**。ダイアログも**新設していない**(既存の未保存確認をそのまま再利用する)。
それでも L5 を求めるのは、**その既存ダイアログが出る条件を新設した**ためである。
SR ユーザーは「確認が出ずに閉じた」のか「確認が出たのに読まれなかった」のかを目で区別できず、
後者はそのまま無自覚のデータ喪失になる。

**PR #36〜#47 分の L5 未実施と合わせて 1 回で実施する**(v0.2 監査 §5)。
本チェックリストはそのうち**本ブランチが追加した分**のみを列挙する。

## 前提

- 設定で **「起動時に前回開いていたファイルを復元する」= ON** かつ **「バックアップ」= ON**
  であること(この 2 つが hot exit の前提ゲート。どちらかが OFF だと従来経路になり本件は再現しない)。
- kxEdit を**終了しておく**こと(①の準備でバックアップフォルダを操作するため)。

### 書込失敗の作り方(実測済みの確実な方法)

`%APPDATA%\kxEdit\backups` **フォルダを消し、同じ位置に同じ名前のファイルを作る**。

```
rmdir /s /q "%APPDATA%\kxEdit\backups"
echo occupied> "%APPDATA%\kxEdit\backups"
```

これで `Directory.CreateDirectory` が `IOException` を投げ、バックアップ書込が確実に失敗する。

> **設計書 §7.4 が当初書いた「フォルダを読み取り専用にする」は使わないこと。**
> 実際に書き込まれるのは配下の `session-{GUID}` サブフォルダなので、ACL の効き方次第で
> 再現しない(Tasks 3+4 レビューの指摘)。上のファイル方式は自動テストとスパイクの
> 両方で実測済み。

**後始末(必ず行う)**: ②の前に元へ戻す。

```
del "%APPDATA%\kxEdit\backups"
```

(フォルダは kxEdit が次回起動時に自動生成する)

## ① 書込失敗時に未保存確認が出て、NVDA が読み上げる

**操作**

1. 上記の手順で `%APPDATA%\kxEdit\backups` をファイルで塞ぐ。
2. kxEdit を起動する。
3. 無題タブに何か入力する(保存はしない)。
4. ウィンドウの **×** で閉じる(Alt+F4 でも可)。

**期待**

- [ ] **未保存確認のダイアログが出る**(従来なら確認なしで閉じていた場面)
- [ ] NVDA がダイアログのタイトルと本文、どのファイルについての確認かを読み上げる
- [ ] 「はい / いいえ / キャンセル」の選択肢が読み上げられ、Tab で移動できる
- [ ] **「キャンセル」を選ぶと終了が中止され**、編集を続けられる(本文が残っている)
- [ ] もう一度 × を押すと、再び同じ確認が出る

**判定の注意**

- **確認が出ずにそのまま閉じたら NG。** それが A-8 そのもので、本ブランチが直している症状。
- 応答までに**最大 5 秒**待たされることがある(申し送り S-A8-6 / S-A8-2)。
  上のファイル方式では書込が即失敗するので実際にはすぐ出るはずだが、
  **数秒固まっても異常ではない**。「フリーズした」と判定しないこと。

## ② 正常時は従来どおり確認なしで閉じ、内容が復元される(回帰)

**操作**

1. `del "%APPDATA%\kxEdit\backups"` で①の細工を戻す。
2. kxEdit を起動する。
3. 無題タブに何か入力する(保存はしない)。名前付きファイルを開いて編集してもよい。
4. ウィンドウの **×** で閉じる。
5. kxEdit を再起動する。

**期待**

- [ ] **確認ダイアログが出ずに閉じる**(hot exit 本来の挙動=退行していないこと)
- [ ] × から終了までに**目立った待ちがない**(体感が変わっていないこと)
- [ ] 再起動すると**編集中の内容がそのまま復元される**(タブに `*` が付いた状態)
- [ ] 復元されたタブで Ctrl+S が正常に効く

**判定の注意**: ここで確認ダイアログが出たら**退行**。①と②は対で判定すること。

---

## ③ 従来の fall-through 経路が変わっていないこと(回帰)

**操作**

1. 設定で **「バックアップ」を OFF** にする(復元は ON のまま)。
2. 無題タブに何か入力する。
3. ウィンドウの **×** で閉じる。

**期待**

- [ ] **従来どおり**未保存確認が出て、NVDA が読み上げる
- [ ] ①と**同じダイアログ**である(文言・選択肢が変わっていないこと)
- [ ] 「いいえ」で破棄して閉じたあと再起動すると、**そのタブが復活しない**

**判定の注意**: 本ブランチは既存の確認ダイアログを再利用しているだけなので、
①と③で読み上げが違ったらどこかがおかしい。

---

## 総合判定

- [ ] ① が OK(**本ブランチの目的そのもの**。NG ならマージしない)
- [ ] ② が OK(退行なし)
- [ ] ③ が OK(退行なし)

①が NG の場合は、①の細工が効いていたか(`%APPDATA%\kxEdit\backups` が
フォルダではなくファイルになっていたか)を先に確認すること。細工が効いていないと
正常系と区別が付かない。
