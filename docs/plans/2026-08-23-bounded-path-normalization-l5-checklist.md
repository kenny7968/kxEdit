## 位置づけ

CLAUDE.md §5 は「L5 が最終ゲート」「判定に迷ったら『必要』に倒す」と定める。

本ブランチは **SR 経路(`kxEdit.Accessibility` / `EditorControl` の UIA 部 / App の Speech 系)を 1 行も触っていない**。それでも L5 を求めるのは、**エラーダイアログの文言を 4 種類新設した**ためである(到達不能 / パス不正 × 保存 / 開く)。SR ユーザーはダイアログを目で確認できないので、読み上げが成立するかは実機でしか判定できない。

**PR #36〜#47 分の L5 未実施と合わせて 1 回で実施する**(v0.2 監査 §8 手順 5)。本チェックリストはそのうち**本ブランチが追加した分**のみを列挙する。

## 前提

- バックアップ / hot exit 復元が有効な設定であること(既定)。
- 到達不能な共有パスを 1 つ用意すること。**実際にネットワークを切る必要はない**:
  `\\192.0.2.1\share\memo.txt`(TEST-NET-1・ルーティングされない)を打てば到達不能として扱われる。

---

## ① SaveAs で到達不能な共有パスを打つ → タイムアウト文言が読み上げられる

**操作**

1. 無題タブに何か入力する。
2. Ctrl+Shift+S で「名前を付けて保存」を開く。
3. ファイル名のテキストボックスに `\\192.0.2.1\share\memo.txt` を**直接入力**して Enter。

**期待**

- [ ] **5 秒程度**で応答が返る(**20 秒以上固まらないこと**。これが S-15 の修正そのもの)
- [ ] 「**保存先に到達できませんでした(5 秒)。ネットワーク接続を確認してください: …**」という趣旨のダイアログが NVDA で読み上げられる
- [ ] ダイアログを閉じると**「名前を付けて保存」に戻り、打った文字列が残っている**(打ち直しを強いられない)
- [ ] 文字コード・改行の選択も保たれている

**判定の注意**: 「パスが正しくありません」と読み上げられたら **NG**。到達不能と打ち間違いを分けることが本ブランチの意図。

---

## ② SaveAs でパス不正を打つ → 別の文言が読み上げられる(①の対照)

**操作**

1. 同じく「名前を付けて保存」のテキストボックスに `C:\` とだけ入力して Enter。

**期待**

- [ ] 即座に応答が返る(待ち時間なし)
- [ ] 「**パスが正しくありません: …**」という趣旨のダイアログが NVDA で読み上げられる
- [ ] **「到達できません」とは読み上げられない**(①と弁別できている)
- [ ] ダイアログを閉じると「名前を付けて保存」に戻る
- [ ] **本文が消えていない**(PR #47 の V-1。無断で `Modified` が落ちて確認なしに本文が消える導線が復活していないこと)

---

## ③ 「開く」で到達不能な共有パスを指定 → タイムアウト文言が読み上げられる

**操作**

1. Ctrl+O で「開く」ダイアログを出し、ファイル名欄に `\\192.0.2.1\share\memo.txt` を直接入力して Enter。

**期待**

- [ ] **5 秒程度**で応答が返る
- [ ] 「**ファイルに到達できませんでした(5 秒)。ネットワーク接続を確認してください: …**」という趣旨のダイアログが NVDA で読み上げられる
- [ ] **タブが増えていない**(作りかけのタブが残らない)
- [ ] 元のタブにフォーカスが戻り、編集を続けられる

---

## ④ 通常操作に退行が無いこと(回帰)

**操作**

1. ローカルのテキストファイルを Ctrl+O で開く。
2. 1 文字編集して Ctrl+S。
3. Ctrl+Shift+S で別名保存。
4. 「最近のファイル」から開き直す。

**期待**

- [ ] いずれも**待ち時間なく**完了する
- [ ] タブのラベル・ステータスバー・保存完了の読み上げが従来どおり
- [ ] 「最近のファイル」に**同じファイルが 2 つ並ばない**

**判定の注意**: 既存 `settings.json` に**未正規化のエントリー**が残っていた場合に限り、同じファイルが最大 1 件重複して並びうる(設計書 §3.4 の受容)。1 度開き直せば解消する。**新規に増え続けるなら NG。**

---

## ⑤ hot exit 復元が従来どおり(回帰)

**操作**

1. 複数タブを開き、うち 1 つを未保存のまま編集する。
2. タスクマネージャーから kxEdit を強制終了する。
3. 再起動する。

**期待**

- [ ] 復元が**待ち時間なく**完了する(タブ数に比例した遅延が出ないこと)
- [ ] 未保存タブが `*` 付きで復元され、本文が保たれている
- [ ] 保存済みタブが同じパスで復元される
- [ ] **同じファイルのタブが 2 つ並ばない**
- [ ] 復元時に**エラーダイアログが増えていない**(復元経路は抑止スコープなので、通常は無言で済む)

---

## ⑥ Task 4B のセキュリティ修正による挙動変更の確認(該当者のみ)

**この項目は、次のいずれかに当てはまる場合だけ実施する**:

- ドライブ文字を割り当てずにマウントしたボリューム上のファイルを開いていた
- `\\?\` や `\\.\` で始まる綴りのパスを使っていた

**期待**

- [ ] hot exit 復元で**無題タブに降格**する(本文は残る)
- [ ] 本文を失わずに「名前を付けて保存」でやり直せる

**判定の注意**: 降格は**意図した挙動変更**。本文が消えたら NG。

---

## 総合判定

- [ ] ①〜⑤ すべて期待どおり
- [ ] ⑥ は該当なし / 期待どおり

**NG が出た場合の切り分け**

- ① / ③ で 20 秒以上固まる → S-15 が塞がっていない。`FileController` の seam 経由が効いていない可能性。
- ① と ② で同じ文言 → `switch` の分岐が効いていない。
- ④ / ⑤ で遅延 → `FindByPath` / `RecentFilesList` の FS 非依存化が効いていない可能性。
- ② で本文が消える → **V-1 の再導入。マージしないこと。**
