## 要否判定

**必要。** 新しい発声文言「選択範囲が変わりました。選択し直してください」が
`IAnnouncer.Say` 経由で 1 つ増えるため、CLAUDE.md §5 の
「App の Speech 系に触れる変更」に該当する。

自動テスト(L3)は `IAnnouncer.Say` に渡された**文字列**までしか検証していない。
**実際に音声が出るか・何回読まれるか・ダイアログ内ステータスと二重に読まれないか**は
実機でしか確認できない。

## 共通の前準備

1. Release 構成でビルドした yEdit を起動する。
2. NVDA を起動しておく(発声の確認が目的なのでスピーチビューアーだけに頼らない)。
3. 新規タブに本文 `abc abc abc` を入力する。
4. `Ctrl+H` で置換ダイアログを開き、検索語 `abc` / 置換後 `X` を入力する。

## 検証項目

### ① 陳腐化拒否の発声(本 PR の中核)

**操作手順**

1. 本文中の**中央**の `abc`(4〜7 文字目)を選択する。
2. 「選択範囲のみ」を ON にする。
3. 本文の**先頭**にカーソルを移し、`QQQQ` と入力する(本文 `QQQQabc abc abc`)。
4. 置換ダイアログへ戻り「すべて置換」を押す。

**期待**

- 「選択範囲が変わりました。選択し直してください」が読まれる。
- **本文が一文字も変わっていない**(`QQQQabc abc abc` のまま)。

### ⑦ 範囲を選んで語を変えながら連続置換できること

置換に成功すると、置換後の同じ領域を新しい世代で捕捉し直す(最終レビュー Important-3)。
これが効いていないと、2 回目で ① の拒否文言が出てしまう。

**操作手順**

1. 本文 `aaa bbb ccc` を用意し、先頭 7 文字 `aaa bbb` を選択する。
2. 「選択範囲のみ」を ON にする。
3. 検索語 `aaa` / 置換後 `LONGER` で「すべて置換」→ 本文 `LONGER bbb ccc`。
4. **選択し直さずに**検索語を `bbb` / 置換後 `Y` に変えて「すべて置換」。

**期待**

- 4 で「1 件置換しました」が読まれる(① の文言**ではない**)。
- 本文が `LONGER Y ccc` になる(範囲外の `ccc` は残る)。

### ⑧ 混在 EOL ファイルの保存でスコープが無効化されること(仕様)

CRLF と LF が混在するファイルは、保存時の EOL 統一でバッファが作り直される
(`FileController.SaveTo` → `EditorControl.ConvertEols`)。char 位置が実際に動くので
拒否が正しい動作だが、「保存しただけなのに」と感じうるため、実機での聞こえ方を確認する。
EOL が統一済みのファイル(大多数)では起きない。

**操作手順**

1. CRLF と LF が混在するファイルを開く。
2. 範囲を選択し「選択範囲のみ」を ON にする。
3. `Ctrl+S` で保存する。
4. 「すべて置換」を押す。

**期待** — 「選択範囲が変わりました。選択し直してください」が読まれ、本文が変わらない。

| 実測発声 | 本文 | 判定 |
|---|---|---|
|  |  | ☐ PASS / ☐ FAIL |

## 付録: 自動化による機能事前検証(2026-08-06 実施)

**これは L5 ではない。** windows-mcp + UI Automation で yEdit を駆動し、NVDA スピーチビューアーから
発声テキストを読み出して照合した記録である。確認できるのは**「NVDA が何を、何回しゃべるか」**まで。
**音声出力そのもの・発声のタイミング・他の発声への割り込み・聞き取りやすさは検証できていない。**
上の全 8 項目は実機 L5 の対象として残る。

実行構成: Release ビルド(`src/yEdit.App/bin/Release/net9.0-windows/yEdit.exe`・fixup 反映後)。
本文とスコープは毎回 UIA の TextPattern で読み、選択内容・チェック状態を**操作前に検証**してから進めた。

| 項目 | 操作 | 実測発声 | 実測本文 | 判定 |
|---|---|---|---|---|
| ① 陳腐化拒否 | `abc abc abc` の中央 [4,7) 捕捉 → 先頭へ `QQQQ` 挿入 → すべて置換 | 「選択範囲が変わりました。選択し直してください」×1 | `QQQQabc abc abc`(無変化) | PASS |
| ② 二重読み | ① をキーボード Alt+A で再実行 | 同文言が**ちょうど 1 回** | 無変化 | PASS |
| ③ 既存文言との区別 | ① の直後にもう一度 すべて置換 | 「選択範囲がありません」 | 無変化 | PASS |
| ④ 正常系 | 中央 [4,7) 捕捉 → 編集せず すべて置換 | 「1 件置換しました」 | `abc X abc` | PASS |
| ⑤ 検索移動後 | [0,7) 捕捉 → 次を検索 ×3 → すべて置換 | 「2 件置換しました」 | `X X abc` | PASS |
| ⑥ 取り直し | 拒否後に選択し直して OFF→ON → すべて置換 | 「1 件置換しました」 | `QQQQX abc abc` | PASS |
| ⑦ 連続置換 | [0,7) 捕捉 → `aaa`→`LONGER` → 選択し直さず `bbb`→`Y` | 「1 件置換しました」 | `LONGER Y ccc` | PASS |
| ⑧ 混在 EOL 保存 | CRLF×2 + 裸 LF×1 のファイルで捕捉 → Ctrl+S → すべて置換 | 「選択範囲が変わりました。選択し直してください」 | 無変化(保存で裸 LF は 1→0 に統一済みを確認) | PASS |

③ は「拒否でスコープを捨てる」(最終レビュー Important-1 の fixup)を同時に実証している
= 1 回目「選択範囲が変わりました」→ 2 回目「選択範囲がありません」。

### 自動化の手法メモ(次回の再現用)

- **NVDA スピーチビューアーの内容は Pane の Name プロパティに露出する**(Edit/Text ではない)。
  UIA で最長の Name を持つ子孫を取ればログ全文が得られる。差分を取れば新規発声だけを抽出できる。
- **座標クリックは使えない。** bash 呼び出しのたびにターミナルが前面へ戻り、クリックが吸われる。
  UIA の InvokePattern / TogglePattern / ValuePattern で駆動すると z 順に依存しない。
- **置換ダイアログは別ウィンドウ**(タイトル `置換`)。メインウィンドウへ Alt+A を送ると
  ファイルメニューが開く。キーボード検証では対象ウィンドウを明示的に前面化する。
- PowerShell 5.1 は .ps1 を ANSI で読むため、**日本語を含むスクリプトは BOM 付き UTF-8 で保存する**
  (CLAUDE.md 環境ノート)。これを外すと UIA の名前照合が黙って全滅する。

### 検証手法で踏んだ失敗(教訓)

- **出力を捨てて成功と決めつけた。** `ValuePattern.SetValue` が同名の Text ラベルにマッチして
  失敗していたのに `>/dev/null 2>&1` で握り潰し、古い検索語のまま「見つかりません」を得ていた。
  コントロール種別で絞り、戻り値を必ず読むこと。
- **チェックボックスを現在値を読まずに toggle した。** ON のままの状態で toggle して OFF にし、
  「選択範囲のみ」が効いていない全文置換を実行していた。結果は「1 件置換しました」で、
  **一見すると別項目の PASS に見えてしまう**。状態を変える操作は「現在値を読んでから目標値へ合わせる」形にする。
- 1 打鍵ずつ送らないと SendKeys の `{RIGHT 4}` は取りこぼす(最初の試行で選択が [4,7) ではなく
  ずれており、危うく誤った PASS/FAIL を出すところだった)。**選択は投入前に必ず UIA で読んで確認する。**
