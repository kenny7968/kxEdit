# L5 実機 SR 検証チェックリスト — yEdit → kxEdit 全面改名

- 日付: 2026-08-21
- 対象ブランチ: `feature/rename-to-kxedit`
- 設計書: [2026-08-21-rename-to-kxedit-design.md](./2026-08-21-rename-to-kxedit-design.md)
- 実装計画: [2026-08-21-rename-to-kxedit.md](./2026-08-21-rename-to-kxedit.md)
- 実行環境: Windows 11 + NVDA(実機)

## 要否判定

**必要。** SR が読み上げる文字列そのものが変わる。

調査の結果、UIA が公開する値に旧名は含まれておらず(`AutomationId` は `"editor"` 固定)、
`kxEdit.Accessibility` / `kxEdit.Editor` にも読み上げ文字列としての旧名はない。
変わるのは **App 層のウィンドウタイトル・ダイアログキャプション・About の 3 種**だけである。

しかし本改名の目的が「**名前を耳で聞き分けられるようにすること**」である以上、
自動テストで検証できない「実際にどう読まれるか」がこの変更の成否そのものになる。
CLAUDE.md §5 の判定基準に照らしても必須。

## 共通の前準備

1. Release 構成でビルドした `kxEdit.exe` を起動する。
2. NVDA を起動しておく(**発声の確認が目的なのでスピーチビューアーだけに頼らない**)。
3. 可能なら PC-Talker 環境の「MyEdit」の読みを思い出せる状態にしておく(項目 ① の比較のため)。

---

## 検証項目

### ① `kxEdit` の読みと MyEdit との聞き分け(本改名の目的そのもの)

**最優先項目。** `kxEdit` を NVDA がどう読むかは実装依存で、実機でしか分からない。
「ケーエックスエディット」を想定しているが、綴り読みするか音節化するかは未知である。

**操作手順**

1. `kxEdit.exe` を起動する。
2. `Alt+Tab` で他のウィンドウへ移り、もう一度 `Alt+Tab` で戻る
   (ウィンドウタイトルを NVDA に読ませる)。

**期待**

- タイトルが読まれる。読みの内容は問わない。
- **「MyEdit(マイエディット)」と聞き間違えないこと。** これが合否の基準である。

| 実測の読み(カタカナで書き取る) | MyEdit と区別できたか | 判定 |
|---|---|---|
|  | ☐ できた / ☐ できない | ☐ PASS / ☐ FAIL |

**FAIL だった場合**: 名称選定からやり直す。設計書 §1.2 に検討済み候補と
各々の衝突理由があるので、そこから再開する。実装は全て機械置換なので、
別の名前への差し替えコストは高くない。

**読みが想定と違った場合(PASS だが要記録)**: 説明書には読みを記載していないので
文書修正は不要。ただし実測の読みをこの表に残し、将来の告知文で使えるようにする。

---

### ② ダイアログキャプションの読み

**操作手順**

1. 新規タブに適当な文字を入力する(未保存の状態を作る)。
2. `Ctrl+W` などでタブを閉じ、保存確認ダイアログを出す。

**期待**

- ダイアログのキャプションが `kxEdit` として読まれる。
- 旧名が読まれない。

| 実測発声 | 判定 |
|---|---|
|  | ☐ PASS / ☐ FAIL |

---

### ③ エディタ本体の読みに退行がないこと

改名は名前空間ごと動かしているため、UIA プロバイダの登録経路に影響が出ていないことを
確かめる。**ここが FAIL なら改名が SR 経路を壊している**ので、マージしてはいけない。

**操作手順**

1. 新規タブに `あいう abc` と入力する。
2. `←` / `→` で 1 文字ずつ移動する。
3. `Ctrl+←` / `Ctrl+→` で単語単位に移動する。
4. `↑` / `↓` で行移動する。
5. 適当な範囲を選択する。

**期待**

- 文字・単語・行・選択のいずれも、改名前と同じように読まれる。
- 無音になる箇所がない。

| 文字単位 | 単語単位 | 行単位 | 選択 | 判定 |
|---|---|---|---|---|
|  |  |  |  | ☐ PASS / ☐ FAIL |

---

### ④ マークダウンプレビューで相対パスの画像が表示されること

改名でプレビューの仮想ホストが `yedit.preview` → `kxedit.preview` に変わったため、
配信とポリシーがずれていないかを目視で確認する。

**なお本項目には本 PR 由来ではない疑義が含まれる。** Task 2 の脆弱性レビューが、
CSP の `base-uri 'none'` と HTML の `<base href="https://kxedit.preview/">` が
同居している点を指摘した。仕様上 `base-uri 'none'` は `<base>` を無効化するため、
相対パスが解決されない可能性がある。改名とは無関係な既存構成だが、
ホスト名が変わった今が確認の好機である。

**操作手順**

1. 適当なフォルダに画像ファイルを置き、同じフォルダに次の内容の `.md` を作る。
   ```
   # 見出し

   ![テスト画像](./test.png)
   ```
2. `kxEdit` で開き、マークダウンプレビューを表示する。

**期待**

- 見出しが表示される(プレビュー自体が動いている証拠)。
- 画像が表示される。

| 見出し | 画像 | 判定 |
|---|---|---|
|  |  | ☐ PASS / ☐ FAIL |

**画像だけ NG だった場合**: 改名の問題ではなく既存の構成問題である可能性が高い。
**本 PR では直さず、別課題として起票する。** 本 PR のマージを止める理由にはしない。
