# L5(実機 SR 検証)チェックリスト — grep ジャンプの行ベース再解決(A-18)

対象ブランチ: `feature/grep-jump-line-resolution`(A-18 + A-3 同型の追従 belt)
設計書: `2026-08-31-grep-jump-line-resolution-design.md` / 実装計画: 同名(`-design` なし)

**このブランチの L5 は必須。** A-18 の症状そのものが「**誤った行番号を自信を持って発声する**」で、
修正の当否は実発声でしか最終判定できない(CLAUDE.md §5)。

## 0. なぜ L5 が必要か(自動テストで届かない範囲)

| 未確認 | なぜ自動テストで届かないか |
|---|---|
| **SR が実際に読む行番号** | `LastAnnouncementForTest` は `_announceLabel.Text` を読むだけ。UIA を経由して NVDA が何を発声するかは別問題 |
| **選択移動による UIA の自動読み上げ**と `_announcer.Say` の**重なり方** | 2 経路が同時に走る。二重読み・取り消し合いは実機でしか観測できない |
| **`Stale` の「内容が変わっています」が実際に届くか** | 文言は L3 で完全一致固定済みだが、SR が読み飛ばす/割り込まれる可能性は実機のみ |
| **弱視ユーザーから見た追従スクロール**(項目 3) | `TopLine` の値は L3 で固定済みだが、「画面上でヒット行が見える」ことは目視のみ |

**実発声は NVDA スピーチビューアーで逐語確認する**(手法は `save-encoding-loss-warning` で確立)。
「ダイアログが出た」ではなく「**何と読み上げたか**」を記録すること。

## 1. 実施手順のノウハウ(前回までに確立済み)

- windows-mcp の `Snapshot` は `use_ui_tree=true` で応答が返らないことがある。
  **`use_ui_tree=false` + スクリーンショットの座標読み**で完走できる。
- kxEdit は**コマンドライン引数を受け取らない**。Ctrl+O 直後の `Type` は、ダイアログの出現を
  スクリーンショットで確認してから打つ(確認せず打つと本文へ流し込む事故が起きる)。
- Alt+M 直後のキー送出は本文に入る(メニュー展開を Wait してから送る)。
- キー送出は他ウィンドウへ漏れることがある。可能なら UIA InvokePattern を使う。
- **`OnActivate` は Enter とダブルクリックでのみ発火する**(`GrepResultsWindow.cs:33` / `:103-104`)。
  一覧を矢印で移動しただけではジャンプしない。**矢印で移動 → Enter** の順で操作すること。

### ⚠️ 保存してはいけない

**本チェックリストの全項目は「未保存編集がある状態」を前提にする。**
途中で Ctrl+S を押すとディスクとバッファが一致してしまい、**A-18 の再現条件そのものが消える**。
PR #56 の L5 で「保存で検証して結果を汚した」前例がある。

## 2. 事前準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動し、スピーチビューアーを開く。
3. 検証用フォルダーに、同じ語を含むテキストファイルを 2 つ以上置く。
   - `a.txt`: 20 行程度。5 行目付近に `needle` を含む行を置く。
   - `b.txt`: 同じく `needle` を含む行を持つ(項目 4 用の「別ファイル」)。
   - `long.txt`: 200 行以上(項目 3 用)。末尾付近に `needle` を含む行を置く。

## 3. チェック項目

### 項目 1 — A-18 本命: 未保存編集のあるタブで正しい行を読むこと ★最重要

| # | 手順 |
|---|---|
| 1 | `a.txt` を開く |
| 2 | **先頭に 3 行挿入する**(Ctrl+Home → 適当な行を 3 行入力)。**保存しない** |
| 3 | grep で `needle` を検索(検索フォルダーは検証用フォルダー) |
| 4 | 結果一覧で `a.txt` のヒットへ矢印で移動 → **Enter** |

**期待**:
- NVDA が読む行番号が、**画面上のキャレット行と一致する**(挿入 3 行ぶん下がった行)
- 一覧が表示していた行内容と、着地した行の内容が一致する
- 「内容が変わっています」は**読まれない**

**修正前の挙動(比較用)**: ディスク基準オフセットで着地するため、**3 行ぶんずれた行**を選択し、
その行を「N 行目」と読み上げていた。

**記録すること**: スピーチビューアーの逐語(ファイル名・行番号)と、画面上のキャレット行番号。
**両者が一致していること**が合格条件。片方だけでは A-18 を検証したことにならない。

**観察事項(合格条件ではない)**: 本手順は `GrepJumpKind.Nearby` を通るが production は `Exact` と
同一扱いで区別を伝えない。設計書 §4 は「着地行を発声で読み上げるのでユーザーが検知できる」と
するが、検知できるのは**一覧の行番号を覚えていた場合だけ**なので、一覧が読んだ行番号
(例「12 行目」)と着地の行番号(例「15 行目」)が違うことに違和感があるか所感を記録する。

### 項目 2 — Stale: 内容が変わっていたら嘘をつかないこと

| # | 手順 |
|---|---|
| 1 | 項目 1 の続き(または `a.txt` を開き直す) |
| 2 | grep で `needle` を検索し、結果一覧を**開いたまま**にする |
| 3 | エディタ側で**ヒット行の内容を丸ごと別の文字列に書き換える**。**保存しない** |
| 4 | 結果一覧の同じヒットへ移動 → **Enter** |

**期待**:
- NVDA が「**(ファイル名) N 行目 内容が変わっています**」と読む
- **選択は起きない**(キャレットが行頭に立つだけ)
- 無関係な行へ黙って飛ばない

**記録すること**: 逐語。特に「内容が変わっています」が**読み飛ばされずに届くか**。
`_announcer.Say` の 1 発声に含まれる文言なので、途中で割り込まれると失われる可能性がある。

### 項目 3 — A-3 同型の追従: 同じヒットへ再ジャンプで画面が戻ること(弱視観点)

**折り返し OFF と ON の両方で 1 回ずつ実施する。**
折り返し ON は退避が `_topSegment != 0` を残す唯一の経路で、**自動テストが通っていない**
(Task 3 レビュー S-2)。

| # | 手順 |
|---|---|
| 1 | `long.txt` を開く |
| 2 | grep で `needle` を検索 → 末尾付近のヒットへ **Enter** でジャンプ(ヒット行が見える) |
| 3 | エディタで**マウスホイールを回して先頭までスクロール**(キャレットは動かさない) |
| 4 | 結果一覧に戻り、**同じヒット**へ再度 **Enter** |

**期待**: キャレット行が画面内に戻る(**目視**)。

**修正前の挙動(比較用)**: `SetSelectionCharRange` が無変化で早期 return するため
`BringCaretIntoView` に到達せず、**スクロール退避したまま**になっていた。

**注意**: 手順 3 でキーボードを使うとキャレットが動いて再現条件が壊れる。**必ずホイールで**退避する。

### 項目 4 — 退行なし: 未オープンの別ファイルへのジャンプ

| # | 手順 |
|---|---|
| 1 | すべてのタブを閉じる |
| 2 | grep で `needle` を検索 |
| 3 | `b.txt`(未オープン)のヒットへ **Enter** |

**期待**: 従来どおりファイル名と行が読まれ、ヒット語が選択されている。
「内容が変わっています」は読まれない。

## 4. 判定

- **項目 1 が NG なら A-18 は直っていない。** マージしない。
- 項目 2 が NG(文言が届かない)の場合は、発声の届け方(タイミング・割り込み)の問題として
  切り分ける。着地位置が正しければ A-18 本体は直っている。
- 項目 3 は弱視観点の追加スコープ(設計書 §3.3)。NG でも A-18 本体の判定には影響しないが、
  PR description に記録する。
- 項目 4 が NG なら退行。マージしない。
