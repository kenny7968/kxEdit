このブランチは L1 / L3 の網が厚い。**だからこそ「網があるからもう安心」と書かない**ために、
何が既に固定されていて、何が実機でしか判らないのかを先に分ける。

## 1. 実施手順のノウハウ(前回までに確立済み)

- windows-mcp の `Snapshot` は `use_ui_tree=true` で応答が返らないことがある。
  **`use_ui_tree=false` + スクリーンショットの座標読み**で完走できる。
- `Type` ツールは**バックスラッシュも先頭文字も落とす**。文字列入力は
  `Clipboard` set → Ctrl+A → Ctrl+V に統一し、投入後に必ず画面で確認する。
- kxEdit は**コマンドライン引数を受け取らない**。Ctrl+O 直後の `Type` は、ダイアログの出現を
  スクリーンショットで確認してから打つ(確認せず打つと本文へ流し込む事故が起きる)。
- Alt+M 直後のキー送出は本文に入る(メニュー展開を Wait してから送る)。
- **ステータスバーの発声ラベルは `IAnnouncer` が読む文字列そのもの**
  (`UiaAnnouncer.Say` が `_label.Text` を無条件に設定する)。スピーチビューアーが使えない場合の
  次善の観測面になるが、**それは「表示」であって「発声」ではない**。PR #57 の第 1 回のように
  「未検証」と書き分けること。

### 1.0 ⚠ F2 編集中にダイアログが出たら、その項目はやり直し

**セル編集オーバーレイはフォーカスを失った瞬間に `CancelEdit` が走って消える**
(`CsvCellEditor.OnLostFocus` → `CancelEdit`)。モーダルダイアログはフォーカスを奪うので、
**F2 編集中に何かのダイアログが出た時点で編集は自動的に取り消されている。**

Ctrl+S が `ConvertEols` に**到達する前に**ダイアログを出して短絡する枝が複数ある:

| 短絡する枝 | 実物 |
|---|---|
| 同じパスを別タブが開いている | `FileController.cs:483` の `_prompt.Error`(`ConvertEols` より前) |
| 現在の文字コードで表せない文字がある(符号化劣化の事前確認・A-10) | 同 `WriteToPath` より前(`_prompt.OkCancel`)。**ただし条件の先頭が `doc.State.Encoding.CodePage != 65001` なので、§2 の BOM なし UTF-8 fixture では構造的に発火しない**(短絡評価で `CanEncodeBuffer` すら呼ばれない)。他文字コードの文書で試すときだけ効く |
| 保存先がリモートで 5 秒プローブに失敗 | `WriteToPath` 冒頭の `TryInspectSaveTarget` |
| 保存自体が失敗(読み取り専用属性・I/O エラー) | `FileController.cs:912` の `UndoEolConversion` で本文を巻き戻したうえで `_prompt.Error`(上限超過なら `:920` / それ以外は `:928` の 2 系統)。なお `UndoEolConversion` は `conversionRecorded=false`(= fast-path で何も記録していない)のときは**何も戻さない** |

**ダイアログが出た = Ctrl+S は `ConvertEols` に届いていない(または届いたが巻き戻された)
= その回の項目 1 / 3 は無効。** fixture を作り直してやり直すこと。
検証用フォルダーはローカルに置き、同じファイルを 2 タブで開かないこと。

### 1.1 発声のスロットリングについて(逐語記録の前提)

`UiaAnnouncer` は **50 ms の throttle + trailing(last-write-wins)** を持つ。本ブランチが増やした
発声は 1 コマンドあたり 1 本だけなので取りこぼしは想定しないが、**セル移動を連打した直後に
Enter を押すと、移動の発声と確定の発声が畳まれうる**。逐語を取るときは
**移動 → 1 拍おく → F2** の順で操作すること。

### 1.2 ⚠ フィクスチャは項目ごとに作り直す

**Ctrl+S を 1 回押した時点で、そのファイルの EOL は統一される。**
= M-25 の再現条件(混在 EOL)が**その場で消える**。同じファイルを次の項目に使い回すと
`ConvertEols` が fast-path へ落ちて何も差し替わらず、**検証が vacuous になる**。
§2 のスクリプトは項目ごとに別名で作る形にしてある。

## 2. 事前準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動し、**スピーチビューアー**(NVDA メニュー → ツール → スピーチビューアー)を開く。
   PR #57 の第 1 回では windows-mcp から NVDA メニューを操作できなかった。
   **開けない場合はユーザーに開いてもらってから開始する。**
3. 検証用フォルダーに**混在 EOL の CSV** を作る。行区切りは CRLF、**セル内改行だけ LF** にする。
   kxEdit で作ってはいけない(保存時に EOL が統一されて混在が消える)。

   ```powershell
   $body = "id,memo,tail`r`n" +
           "1,`"x`ny`",t1`r`n" +
           "2,m2,t2`r`n" +
           "3,m3,t3"
   $enc = [Text.UTF8Encoding]::new($false)   # BOM なし UTF-8
   foreach ($n in 'mix1a','mix1b','mix3','mix4','mix7') {
       [IO.File]::WriteAllText((Join-Path $PWD "$n.csv"), $body, $enc)
   }

   # 1-C は鏡像(セル内が CRLF・行区切りが LF)。EOL の多数決が LF 側に倒れる。
   $mirror = "id,memo,tail`n" +
             "1,`"x`r`ny`",t1`n" +
             "2,m2,t2`n" +
             "3,m3,t3"
   [IO.File]::WriteAllText((Join-Path $PWD 'mix1c.csv'), $mirror, $enc)
   ```

4. **作った直後にバイトを検算する**(混在していなければ全項目が vacuous になる)。

   ```powershell
   foreach ($n in 'mix1a','mix1c') {
       $b = [IO.File]::ReadAllBytes((Join-Path $PWD "$n.csv"))
       $crlf = 0; $lone = 0
       for ($i = 0; $i -lt $b.Length; $i++) {
           if ($b[$i] -eq 0x0A) { if ($i -gt 0 -and $b[$i-1] -eq 0x0D) { $crlf++ } else { $lone++ } }
       }
       "$n len=$($b.Length) CRLF=$crlf LoneLF=$lone"
   }
   # 期待: mix1a len=42 CRLF=3 LoneLF=1 / mix1c len=40 CRLF=1 LoneLF=3
   ```

5. **ディスク監視を先に走らせておく(項目 1 の必須観測「前提 C」・項目 3 の EOL 統一確認)。**
   F2 編集中にターミナルへ切り替えると**その瞬間にオーバーレイが消える**(§1.0)ので、
   **編集中のディスク状態は「先に仕掛けたループ」でしか観測できない。**
   kxEdit を起動する前に、別のターミナルで次を走らせたままにする。

   ```powershell
   $dir = $PWD
   $log = Join-Path $dir 'eol-watch.log'
   $last = @{}
   while ($true) {
       foreach ($f in Get-ChildItem -Path $dir -Filter 'mix*.csv') {
           # 保存は AtomicFile(tmp へ書いて File.Replace)なので、200ms ポーリングが
           # 差し替えの瞬間と衝突すると共有違反で落ちる。**それは前提 C を記録すべき
           # まさにその瞬間**なので、握って次の周回へ進む(ループごと死なせない)。
           try { $b = [IO.File]::ReadAllBytes($f.FullName) } catch { continue }
           $crlf = 0; $lone = 0
           for ($i = 0; $i -lt $b.Length; $i++) {
               if ($b[$i] -eq 0x0A) {
                   if ($i -gt 0 -and $b[$i-1] -eq 0x0D) { $crlf++ } else { $lone++ }
               }
           }
           $sig = "$($f.Name) len=$($b.Length) CRLF=$crlf LoneLF=$lone"
           if ($last[$f.Name] -ne $sig) {
               "{0} {1}" -f (Get-Date -Format 'HH:mm:ss.fff'), $sig |
                   Out-File -Encoding utf8 -Append $log
               $last[$f.Name] = $sig
           }
       }
       Start-Sleep -Milliseconds 200
   }
   ```

   作成直後の各ファイルは `len=42 CRLF=3 LoneLF=1` として記録される。
   **編集中 Ctrl+S が `ConvertEols` まで届けば、そこに `len=43 CRLF=4 LoneLF=0` が 1 行増える。**

6. 設定の「.csv を開いたら CSV モードへ入る」を確認する。
   **既定は OFF**(`AppSettings.CsvAutoModeOnOpen` は初期化子を持たない = `false`)なので、
   既定設定のままなら開いたあと **モード(&M) → CSVモード(&C)** で手動で入る。

### 2.1 フィクスチャの論理形(発声の期待値を導くため)

| | 1 列目 (`id`) | 2 列目 (`memo`) | 3 列目 (`tail`) |
|---|---|---|---|
| **1 行目** | `id` | `memo` | `tail` |
| **2 行目** | `1` | `x`⏎`y`(**セル内 LF**) | `t1` |
| **3 行目** | `2` | `m2` | `t2` |
| **4 行目** | `3` | `m3` | `t3` |

- **項目 1-A の編集対象 = 2 行 2 列**(セル内改行を持つセル。L3 の `MixedEolCsv` に対応)。
- **項目 1-B の編集対象 = 3 行 1 列**(セル内改行より**後ろの行**のセル。`ShiftOnlyCsv` に対応)。
- **項目 1-C(`mix1c.csv`)は同じ論理形の鏡像**。行区切りが LF、memo セル内だけ CRLF。
  編集対象は 1-A と同じ **2 行 2 列**(`CrlfInCellLfBodyCsv` に対応)。
- 開いた直後の EOL 表示(ステータスバー)は **必ず CRLF になる**。
  `LineEndingDetector.Detect` は単純多数決(`crlf >= lf && crlf >= cr` なら CRLF)で、
  この fixture は CRLF 3 : LF 1 : CR 0。開いた文書の `State.LineEnding` はこの検出結果
  (`FileController.cs:359`)なので、設定の既定改行コードは影響しない。
  **LF や CR と表示されたら fixture が壊れている**(§2-4 のバイト検算に戻って作り直す)。
  そのまま進めると `ConvertEols` の向きが変わり、1-A は `length` の陳腐化を殺せなくなる。
- **`mix1c.csv` は逆に必ず LF になる**(CRLF 1 : LF 3 : CR 0 →
  `crlf >= lf` が false なので `lf >= cr` 側 = LF)。**1-C で CRLF と表示されたら
  fixture が壊れている。** 1-C は「EOL 表示が LF であること」が非 vacuity の条件である。

### 2.2 期待する発声の逐語(定数の実物)

文言は `src/kxEdit.Core/Csv/CsvAnnounceFormatter.cs` から引いている。**記憶で書き換えないこと。**

| 場面 | 逐語 |
|---|---|
| CSV モード進入(キャレット先頭) | `CSVモード オン id 1行1列` |
| 2 行 1 列へ移動 | `1 2行1列` |
| **2 行 2 列(セル内改行あり)へ移動** | `制御文字を含みます: x y 2行2列` |
| 3 行 1 列へ移動 | `2 3行1列` |
| 確定後(値 `NEW`) | `NEW 2行2列` |
| 拒否枝(項目 6・**到達経路なし**) | `本文が変わったため確定できません。入力は破棄しました` |

> **「制御文字を含みます: 」が付くのは仕様である**(UIA-M-1)。`CsvAnnounceFormatter.Cell` は
> `SanitizeForDisplay.ContainsSanitizableControlChar` で判定し、**CR / LF も `UnicodeCategory.Control`
> なのでこの分岐に入る**。続く値は `OneLine(value, 60)` で 1 行化され、**改行は空白 1 個へ畳まれる**
> (`x\ny` も `x\n\ny` も同じ `x y` になる)。本ブランチが変えた挙動ではない。

### 項目 1 — M-25 本命: F2 編集中の Ctrl+S → Enter ★最重要・マージブロッカー

#### 1-A: セル内改行を持つセルを編集する(`mix1a.csv`)

### 項目 6 — `CommitTargetChanged` の発声 → **未確認・到達経路なし**

**この項目には判定欄を置かない。PASS も FAIL も書けないからである。**

新しい発声 `本文が変わったため確定できません。入力は破棄しました` は、
**現行の配線では実運用から踏めない。** 設計書 §6 の項目 3 は「実機では確認できない見込み。
判断は実装時に確定する」と書いていた。**その判断を下してここに記録する。**

この発声を出す条件は**独立に 3 つ**ある(`CsvAnnounceFormatter.CommitTargetChanged` の doc):

1. セルが別物へ変わっていた(**値または行列の形**が不一致)
2. セルが消えていた(`GetField` が `null`)
3. **本文が CSV として壊れた**(`CsvDocument.Ok == false`)—— (1)(2) から導けない独立のケース。
   末尾に未終端引用符のレコードが付くと、**行数・列数・値がすべて開始時と一致したまま
   `Ok` だけが false になる**(設計書 §8.19 に L1 実測)。

いずれも「F2 編集中に本文が変わる」ことが前提である。F2 編集中に本文へ届く経路を実コードで
1 本ずつ当たった結果:

| 経路 | 本文を変えるか | F2 編集中の扱い | 根拠(実コード) |
|---|---|---|---|
| **Ctrl+S(上書き保存)が成功** | **変える** | 素通り。**ただし `ConvertEols` は CR / LF しか触らない**ので行列構造も正規化後の値も変わらず、**必ず受理枝**へ行く | `MainForm.cs` の `!_csv.IsEditing` ガードと `Ctrl+S` メニューショートカット / `FileController.WriteToPath` の `ConvertEols` |
| Ctrl+S が `ConvertEols` **前**に短絡 | **変えない** | 重複タブ(`:483`)/ 符号化劣化の事前確認 / リモート到達性(`TryInspectSaveTarget`)。いずれもダイアログ → `CancelEdit` = 確定自体が起きない | `FileController.cs` / `CsvCellEditor.OnLostFocus` |
| Ctrl+S が**書込で失敗** | 変えて**戻す** | `UndoEolConversion`(`:912`)が変換を 1 Undo 取り消し(`ReadOnly` ガード無し)、直後に `_prompt.Error`(`:928`)→ `CancelEdit`。本文は開始時と同一に戻る | `FileController.WriteToPath` の catch |
| Undo / Redo / 切り取り / 貼り付け | 変えるはず | **`ReadOnly` ガードで no-op**。CSV モードは `ReadOnly=true` | `EditorControl.cs` の `Undo` / `Redo` / `Cut` / `Paste`。**第 1 文は `if (IsComposing) CancelCompositionAndDefault();` で、`if (_buffer is null \|\| ReadOnly) return;`(`Paste` だけ `return false;`)はその次** |
| 置換 / 一括置換 | 変えるはず | CSV モードで拒否・発声。書込 API 側にも `ReadOnly` ガードがある | `SearchController` の CSV ガード / `ReplaceCharRange(Exact)` 冒頭 |
| 禁則整形(Ctrl+Shift+J) | 変えるはず | CSV モードで拒否・発声 | `KinsokuFormatController` |
| 開く / 名前を付けて保存 / 検索 / 置換 / grep / 行へ移動(Ctrl+G)/ 設定 | 変えうる | **ダイアログがフォーカスを奪う** → `TextBox.LostFocus` → `CancelEdit`(確定自体が起きない)。なお F2 編集中の Ctrl+G は CSV の「セルへ移動」ではなく `MainForm.GoToLine()` に落ちる(CSV の素キー表は `IsEditing` で無効化されているため) | `CsvCellEditor.OnLostFocus` / `MainForm.cs:749` |
| 新規 / タブ切替(Ctrl+Tab・Ctrl+1..9)/ タブを閉じる | 別文書 | `BeforeActiveChange` / `CloseActiveTab` が `AbortEdit`(コールバックを呼ばない) | `MainForm.cs` |
| F3 / Shift+F3 / Insert / Ctrl+Alt+P | **変えない** | `ProcessCmdKey` が `IsEditing` を見ずに**横取りして `true` を返す**(オーバーレイ TextBox には渡らない)。ただし本文には触らない | `MainForm.cs:732-753` の `switch (keyData)` |
| メニューやエディタを**クリック** | — | フォーカスが移る → `CancelEdit` | `CsvCellEditor.OnLostFocus` |
| バックアップ(hot exit)タイマー | **変えない** | ディスクへ書くだけ | `BackupCoordinator` |

**結論: 実機で踏む手順は見つかっていない。** したがってこの発声は
**「未確認(到達経路なし)」のまま L5 を終える。** 「確認済み」とも「網がある」とも書かないこと。

- この枝を守っているのは **L3 の 9 本だけ**であり、テストからしか踏めない
  (テスト本体のコメントが「以下 9 本が踏む枝は、現行の配線では実運用から到達できない」と明記)。
  **本数は網の増減で変わる**(`d9c1b0e` で 7 → 9)。引用するときは数え直すこと。
- **3 番目の条件(`Ok == false`)も同じく到達しない。** `ConvertEols` は CR / LF 以外のバイトに
  触れないので引用符の対応を崩せず、`Ok` を true から false へ転じさせられない。
- **「到達不能」自体もこのブランチの実測範囲を超えている。** `ConvertEols` が行列構造を変えない
  ことは T1 / T2 の **2 fixture 分だけが実測**で、一般には設計書 §4.4 の**論証**である
  (§8.9 が「§4.4 の全体が実測になったわけではない」と釘を刺している)。
- **将来 F2 編集中に本文を変える配線が 1 本増えたら、この項目は実機で踏めるようになる。**
  そのときは本項目を通常のチェック項目へ昇格させること。
- 実施者が上の表に無い到達手順を思いついたら**試して記録する**。踏めたなら
  逐語(`本文が変わったため確定できません。入力は破棄しました`)と、本文が 1 文字も
  変わっていないことを確認する。

### 項目 7 — 退行なし: 本文を変えずに F2 → Enter(通常の主経路)

**自動テストが届かない範囲**: 本文と発声は L3 で固定済み(`BeginEdit_ThenCommit_...`)。
**実機で見るのは、新しい同一性検証が通常操作を誤って拒否しないこと。**
guard が誤っていれば、**普通にセルを編集しただけで
`本文が変わったため確定できません。入力は破棄しました` が読まれて入力が捨てられる。**
これは実運用で最も痛い失敗様式であり、実機で最も早く出る。

| # | 手順 |
|---|---|
| 1 | **一度も Ctrl+S していない `mix7.csv`** を開き CSV モードに入る(**この項目では Ctrl+S を押さない**) |
| 2 | **改行を含まないセル**(例 3 行 3 列 = `t2`)で F2 → `AAA` → Enter |
| 3 | **セル内改行を持つセル**(2 行 2 列)で F2 → 中身を変えずに **Enter**(no-op 確定) |
| 4 | 続けて 2 〜 3 セルを編集して Enter を繰り返す |

| 確認 | 期待 | 判定 |
|---|---|---|
| 発声(手順 2) | `AAA 3行3列`。**`本文が変わったため確定できません` は読まれない** | |
| 発声(手順 3) | `制御文字を含みます: x y 2行2列`(値は変わらない)。**拒否されない** | |
| 本文(手順 3 のあと・**目視**) | 2 行 2 列がまだ **2 表示行**にまたがる(セル内改行が失われていない) | |
| 本文 | 各回、狙ったセルだけが変わる | |
| テンポ | 連続確定で発声が詰まったり前の発話が残ったりしない(§1.1 の throttle) | |

> **この項目は EOL 正規化(§8.24 の m5)を踏まない。** 手順 3 は編集中に本文を変えないので、
> 開始時の値と確定時の値は**同じ生文字列**(`doc.ParseCsv()` はスナップショット参照が同じなら
> 同一インスタンスを返す)であり、**正規化を外しても一致して受理される**。
> m5 を殺すのは L3 でも T1 の 1 本だけで、実機で対応するのは**項目 1-A** である
> (そちらの「もう 1 つの FAIL 様式」に書いた)。**ここに書くと偽の安全宣言になる。**
>
> **一方、手順 3 でしか踏めない経路がある**: `CsvCellEditor.Begin` は
> `TextBox.Text = field.Value`(セル内改行は **LF 単独**)で初期値を入れ、`Commit` は
> `TextBox.Text` を**読み戻す**。この往復は L3 が一度も通っていない(テストは `Text` を
> 直接上書きしてから `Commit` する)。ネイティブ EDIT コントロールが LF 単独をどう保持するかは
> 実機でしか判らないので、**オーバーレイに 2 行で表示されるか**と
> **確定後に改行が残るか**を必ず記録すること。

## 4. 判定

- **項目 1-A / 1-B / 1-C が FAIL なら M-25 は直っていない。マージしない。**
- **前提が 1 つでも取れなかった回は、他の行が全部 PASS でも項目 1 を PASS にしない。**
  修正前の実装でも同じ結果になるので、**その回は何も弁別していない**。
  「PASS」ではなく「**弁別不能・再実施**」と書く。**必要な前提はケースごとに違う**:

  | ケース | 前提 A(ダイアログ無し) | 前提 B(強調が消える) | 前提 C(ログ) | 前提 D(ディスク) |
  |---|---|---|---|---|
  | 1-A | 要 | 要 | 要(`len=43 CRLF=4 LoneLF=0`) | 要(セル内が `0D 0A`)|
  | 1-B | 要 | **対象外**(オーバーレイがセルを覆う) | **要・弁別の主体** | 任意 |
  | 1-C | 要 | 要 | 要(`len=39 CRLF=0 LoneLF=4`) | 任意 |
- 前提 A〜D が**繰り返し取れない**(Ctrl+S がそもそも `ConvertEols` に届かない)場合は、
  合否ではなく**このブランチの前提そのものの訂正**として扱い、設計書 §2.2 / §3 の読解を
  実測で置き換える記述を §8 へ追記する。M-25 の到達経路が実は無かったことになるので、
  PR description の位置づけも書き換える。
- **項目 7 が FAIL なら退行。マージしない**(通常編集が拒否されるのは M-25 より重い)。
- **項目 2 が FAIL なら退行。マージしない**(ディスクへ壊れた内容が落ちている)。
- 項目 3 / 4 / 5 の FAIL は**要調査**。M-25 本体の判定には影響しないが、
  項目 4 の「空行が消える」は Task 1 の網が主張している事実の否定なので、
  FAIL なら L1 / L3 の網と実装のどちらが誤っているかを切り分ける。
- **項目 6 は判定しない。**「未確認(到達経路なし)」と書いて終える。
  PR description の申し送りにも同じ言葉で残すこと。

## 5. 束ね直しのときの申し送り(傘設計書 §7.2)

傘設計書 §7.2 は「機能単位で束ね直す。検索・置換・保存・バックアップ復元は重複操作が多い」と
定めている。**本チェックリストが他と重複する操作は次のとおり。**

| 本書の項目 | 重複先 | 束ね方 |
|---|---|---|
| 項目 1(A/B/C)/ 2 / 3(F2 編集中の Ctrl+S = `ConvertEols`) | **PR #54 の L5**(`2026-08-28-eol-detection-and-undo-l5-checklist.md` の ①②⑤⑥) | **操作の種類は同じ**(混在 EOL を Ctrl+S で統一する)ので**実施の段取りだけまとめられる**。**フィクスチャは共有できない** —— 理由は拡張子ではなく次の 2 つ(下の注を参照) |
| 項目 3(取消側) | **PR #54 の ⑦**(CSV グリッドモードでのロールバック) | **兼ねられない。前提が排他である。** ⑦ は「読み取り専用属性の CSV を CSV モードで Ctrl+S」= **書込失敗**経路で、`UndoEolConversion`(`FileController.cs:912`)が本文を巻き戻したうえで `_prompt.Error`(`:928`)がモーダルを出す → `CsvCellEditor.OnLostFocus` → **`CancelEdit` がその場で走りオーバーレイが消える**。項目 3 の手順「Ctrl+S → `ZZ` と打つ → Esc」は**打てず**、しかも本文が巻き戻るので「本文が差し替わった状態で Esc する」という前提自体が消える(= 兼ねると項目 3 が完全に vacuous になる)。**⑦ = 書込失敗経路 / 項目 3 = 書込成功後の取消経路**として別々に実施する |
| 項目 1 / 7 のセル移動と発声 | **B5 の M-8**(`UiaAnnouncer` の窓外 Raise が保留 trailing を取り消さず、CSV で → 連打後に 1 セル前が最後に読まれる) | **同じ CSV モードのセル移動発声**。本書 §1.1 が「移動 → 1 拍 → F2」を要求しているのに対し、M-8 は**連打**を要求する。**順序を分ける**こと(M-8 の連打検証を先に済ませてから本書へ入る) |
| 項目 2(保存 → 閉じる → 開き直す) | **B4(保存の最終防衛線)** | 保存経路の退行確認として共有できる |
| 項目 4(Alt+Enter のセル内改行) | なし | CSV 固有。単独で残す |
| 項目 6 | なし(**実施項目ではない**) | 束ね直しの項目数に数えない |

> **fixture を共有できない理由(訂正)**: 当初「#54 の fixture は `.txt` だから CSV モードに
> 入れない」と書いたが**これは偽**である。`CsvController.TryEnterMode` に拡張子判定は無く、
> 見ているのは `doc.ParseCsv().Ok` だけ(拡張子を見るのは `MainForm.AutoEnterCsvMode` の
> **自動進入**だけ)。したがって `.txt` でもモード(&M) → CSVモード(&C) で入れる。
> 共有できない本当の理由は 2 つ:
>
> 1. **内容の条件が違う。** 本書の 1-A / 1-C は「**引用符で囲まれたセル内改行**を持つセル」が
>    要るが、#54 の `mixed-eol.txt` などにそれは無い(足すと #54 側の条件を壊す)。
> 2. **混在 EOL は Ctrl+S 1 回で消える**(§1.2)。#54 の ①②⑤⑥ も本書の項目 1 / 3 も
>    「まだ統一されていない状態」を消費するので、**1 ファイルは 1 観測にしか使えない**。
>
> 逆に言うと、**#54 の `mixed-eol.txt` を CSV モードに入れれば 1-B 型(オフセットずれのみ)の
> 観測は原理的に可能**である。ただし #54 の ② がその混在 EOL を先に消費するので、
> 束ねるなら**どちらが先にその 1 回を使うかを決める**こと。

**検索・置換・バックアップ復元とは重複しない。** 本ブランチは `SearchController` にも
バックアップ経路にも触れていない(設計書 §3 の到達経路表)。束ね直しのときにこの 2 つの
機能グループへ本書の項目を混ぜないこと。
