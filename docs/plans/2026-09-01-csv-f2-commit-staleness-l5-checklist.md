## 0. なぜ L5 が必要か(自動テストで届く範囲/届かない範囲)

このブランチは L1 / L3 の網が厚い。**だからこそ「網があるからもう安心」と書かない**ために、
何が既に固定されていて、何が実機でしか判らないのかを先に分ける。

### 0.1 自動テストで既に固定されている事実(L5 で確かめ直さない)

| 事実 | 網 |
|---|---|
| 混在 EOL を `ConvertEols` してから確定すると、**編集したセルだけ**が書き換わる | L3 `Commit_AfterEolConversion_WritesEditedCell_NotStaleOffsets` / `..._WritesShiftedCell_...` |
| 拒否枝の文言が `本文が変わったため確定できません。入力は破棄しました` である | L3 6 本(全件固定を含む) |
| セル内改行の EOL 正規化規則(連続改行を畳まない・`\r\n` / `\r` → `\n`) | L1 `CsvWriterTests` の `NormalizeEols` 群 |
| `ConvertEols` が `ReadOnly=true` のまま本文を差し替えること | L3 T1 / T2 の `Assert.True(ConvertEols(...))`(設計書 §8.12) |

### 0.2 L5 でしか確かめられない事実(本チェックリストの存在理由)

| 未確認 | なぜ自動テストで届かないか |
|---|---|
| **Ctrl+S が F2 編集オーバーレイを閉じずに `ConvertEols` まで届くこと** | **このブランチの前提そのものだが、自動テストは 1 行も検証していない。** L3 は `MainForm.ProcessCmdKey` も `FileController` も通さず `doc.Editor.ConvertEols(...)` を**直接**呼んで同じ状態を作っている(テスト本体のコメントに明記)。「Ctrl+S がメニューショートカットへ素通りし、オーバーレイがフォーカスを保ったまま残る」は**設計書 §2.2 の読解**であって実測ではない |

## 1. 実施手順のノウハウ(前回までに確立済み)

- windows-mcp の `Snapshot` は `use_ui_tree=true` で応答が返らないことがある。
  **`use_ui_tree=false` + スクリーンショットの座標読み**で完走できる。
- `Type` ツールは**バックスラッシュも先頭文字も落とす**。文字列入力は
  `Clipboard` set → Ctrl+A → Ctrl+V に統一し、投入後に必ず画面で確認する。
- kxEdit は**コマンドライン引数を受け取らない**。Ctrl+O 直後の `Type` は、ダイアログの出現を
  スクリーンショットで確認してから打つ(確認せず打つと本文へ流し込む事故が起きる)。
- Alt+M 直後のキー送出は本文に入る(メニュー展開を Wait してから送る)。
- **ステータスバーの発声ラベルは `IAnnouncer` が読む文字列そのもの**
  (`UiaAnnouncer.Say` が `_label.Text` を無条件に設定する)。スピーチビューアーが使えない場合の
  次善の観測面になるが、**それは「表示」であって「発声」ではない**。PR #57 の第 1 回のように
  「未検証」と書き分けること。

### 1.1 発声のスロットリングについて(逐語記録の前提)

`UiaAnnouncer` は **50 ms の throttle + trailing(last-write-wins)** を持つ。本ブランチが増やした
発声は 1 コマンドあたり 1 本だけなので取りこぼしは想定しないが、**セル移動を連打した直後に
Enter を押すと、移動の発声と確定の発声が畳まれうる**。逐語を取るときは
**移動 → 1 拍おく → F2** の順で操作すること。

### 1.2 ⚠ フィクスチャは項目ごとに作り直す

**Ctrl+S を 1 回押した時点で、そのファイルの EOL は統一される。**
= M-25 の再現条件(混在 EOL)が**その場で消える**。同じファイルを次の項目に使い回すと
`ConvertEols` が fast-path へ落ちて何も差し替わらず、**検証が vacuous になる**。
§2 のスクリプトは項目ごとに別名で作る形にしてある。

## 2. 事前準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動し、**スピーチビューアー**(NVDA メニュー → ツール → スピーチビューアー)を開く。
   PR #57 の第 1 回では windows-mcp から NVDA メニューを操作できなかった。
   **開けない場合はユーザーに開いてもらってから開始する。**
3. 検証用フォルダーに**混在 EOL の CSV** を作る。行区切りは CRLF、**セル内改行だけ LF** にする。
   kxEdit で作ってはいけない(保存時に EOL が統一されて混在が消える)。

   ```powershell
   $body = "id,memo,tail`r`n" +
           "1,`"x`ny`",t1`r`n" +
           "2,m2,t2`r`n" +
           "3,m3,t3"
   $enc = [Text.UTF8Encoding]::new($false)   # BOM なし UTF-8
   foreach ($n in 'mix1a','mix1b','mix3','mix4') {
       [IO.File]::WriteAllText((Join-Path $PWD "$n.csv"), $body, $enc)
   }
   ```

4. **作った直後にバイトを検算する**(混在していなければ全項目が vacuous になる)。

   ```powershell
   $b = [IO.File]::ReadAllBytes((Join-Path $PWD 'mix1a.csv'))
   $crlf = 0; $lone = 0
   for ($i = 0; $i -lt $b.Length; $i++) {
       if ($b[$i] -eq 0x0A) { if ($i -gt 0 -and $b[$i-1] -eq 0x0D) { $crlf++ } else { $lone++ } }
   }
   "CRLF=$crlf LoneLF=$lone"    # 期待: CRLF=3 LoneLF=1
   ```

5. 設定の「.csv を開いたら CSV モードへ入る」が OFF なら、開いたあと
   **モード(&M) → CSVモード(&C)** で入る。

### 2.1 フィクスチャの論理形(発声の期待値を導くため)

| | 1 列目 (`id`) | 2 列目 (`memo`) | 3 列目 (`tail`) |
|---|---|---|---|
| **1 行目** | `id` | `memo` | `tail` |
| **2 行目** | `1` | `x`⏎`y`(**セル内 LF**) | `t1` |
| **3 行目** | `2` | `m2` | `t2` |
| **4 行目** | `3` | `m3` | `t3` |

- **項目 1-A の編集対象 = 2 行 2 列**(セル内改行を持つセル。L3 の `MixedEolCsv` に対応)。
- **項目 1-B の編集対象 = 3 行 1 列**(セル内改行より**後ろの行**のセル。`ShiftOnlyCsv` に対応)。
- 開いた直後の EOL 表示(ステータスバー)は多数決で **CRLF** になるはず(CRLF 3 : LF 1)。
  **LF と表示された場合も検証は成立する**(変換の向きが逆になり、オフセットは前へずれる)。
  どちらだったかを記録すること。

### 2.2 期待する発声の逐語(定数の実物)

文言は `src/kxEdit.Core/Csv/CsvAnnounceFormatter.cs` から引いている。**記憶で書き換えないこと。**

| 場面 | 逐語 |
|---|---|
| CSV モード進入(キャレット先頭) | `CSVモード オン id 1行1列` |
| 2 行 1 列へ移動 | `1 2行1列` |
| **2 行 2 列(セル内改行あり)へ移動** | `制御文字を含みます: x y 2行2列` |
| 3 行 1 列へ移動 | `2 3行1列` |
| 確定後(値 `NEW`) | `NEW 2行2列` |
| 拒否枝(項目 6・**到達経路なし**) | `本文が変わったため確定できません。入力は破棄しました` |

> **「制御文字を含みます: 」が付くのは仕様である**(UIA-M-1)。`CsvAnnounceFormatter.Cell` は
> `SanitizeForDisplay.ContainsSanitizableControlChar` で判定し、**CR / LF も `UnicodeCategory.Control`
> なのでこの分岐に入る**。続く値は `OneLine(value, 60)` で 1 行化され、**改行は空白 1 個へ畳まれる**
> (`x\ny` も `x\n\ny` も同じ `x y` になる)。本ブランチが変えた挙動ではない。

### 項目 4 — Alt+Enter のセル内改行が確定で保たれること(`mix4.csv`)

**自動テストが届かない範囲**: `CsvCellEditor.OnKeyDown` の Alt+Enter 分岐は L3 が一度も通っていない
(テストは `TextBox.Text` を直接代入する)。**この経路は実運用の主経路**であり、
Task 1 のコード品質レビュー(設計書 §8.6)が「畳み込み変異ならユーザーの空行が黙って消える」と
判定した箇所そのものである。

| # | 手順 |
|---|---|
| 1 | `mix4.csv` を開き CSV モード。**3 行 2 列**(`m2`)へ移動 → F2 |
| 2 | 全選択されているので `x` と打つ → **Alt+Enter を 2 回** → `y` と打つ |
| 3 | **Enter** で確定 |
| 4 | **Ctrl+S** して閉じ、バイトを検算する |

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文(**目視**) | 3 行 2 列が `"x` / (空行) / `y"` の **3 表示行**にまたがる。**空行が消えていない** | |
| 強調 | そのセル全体(引用符込み)に掛かっている | |
| 発声 | `制御文字を含みます: x y 3行2列` | |
| 保存後のバイト | `22 78 0D 0A 0D 0A 79 22`(= `"x`CRLF CRLF`y"`)が現れる | |

> **重要(発声では検証できない)**: `OneLine` は連続改行を空白 1 個へ畳むので、
> **`x`⏎`y` と `x`⏎⏎`y` の発声は完全に同一**(`制御文字を含みます: x y ...`)である。
> = **空行が消えたかどうかは発声からは判らない。** この項目の合否は**目視とバイト**で決める。
> SR ユーザーが空行の有無を耳で確かめる手段が無いこと自体を**申し送り候補**として記録する。
>
> なお `CsvWriter.EscapeField` はセル内改行を常に `\n` で書くので、**保存前**のバイトは
> `0A 0A` である。`0D 0A 0D 0A` になるのは Ctrl+S の `ConvertEols` を通った後
> (設計書 §7 の申し送り = 本件以前からの挙動)。

### 項目 6 — `CommitTargetChanged` の発声 → **未確認・到達経路なし**

**この項目には判定欄を置かない。PASS も FAIL も書けないからである。**

新しい発声 `本文が変わったため確定できません。入力は破棄しました` は、
**現行の配線では実運用から踏めない。** 設計書 §6 の項目 3 は「実機では確認できない見込み。
判断は実装時に確定する」と書いていた。**その判断を下してここに記録する。**

拒否枝へ入るには「F2 編集中に本文が変わり、かつ CSV の行数・その行の列数・
編集セルの正規化後の値のいずれかが変わる」ことが要る。F2 編集中に本文へ届く経路を実コードで
1 本ずつ当たった結果:

| 経路 | 本文を変えるか | F2 編集中の扱い | 根拠(実コード) |
|---|---|---|---|
| **Ctrl+S(上書き保存)** | **変える** | 素通り。**ただし `ConvertEols` は CR / LF しか触らない**ので行列構造も正規化後の値も変わらず、**必ず受理枝**へ行く | `MainForm.cs` の `!_csv.IsEditing` ガードと `Ctrl+S` メニューショートカット / `FileController.WriteToPath` の `ConvertEols` |
| 保存が失敗したとき | 変えて**戻す** | `UndoEolConversion` が変換を 1 Undo 取り消す(`ReadOnly` ガード無し)。差引き本文は開始時と同一 → 受理枝 | `FileController.WriteToPath` の catch |
| Undo / Redo / 切り取り / 貼り付け | 変えるはず | **`ReadOnly` ガードで no-op**。CSV モードは `ReadOnly=true` | `EditorControl.cs` の `Undo` / `Redo` / `Cut` / `Paste` 冒頭 `if (_buffer is null \|\| ReadOnly) return;` |
| 置換 / 一括置換 | 変えるはず | CSV モードで拒否・発声。書込 API 側にも `ReadOnly` ガードがある | `SearchController` の CSV ガード / `ReplaceCharRange(Exact)` 冒頭 |
| 禁則整形(Ctrl+Shift+J) | 変えるはず | CSV モードで拒否・発声 | `KinsokuFormatController` |
| 開く / 名前を付けて保存 / 検索 / 置換 / grep / セル移動(g) / 設定 | 変えうる | **ダイアログがフォーカスを奪う** → `TextBox.LostFocus` → `CancelEdit`(確定自体が起きない) | `CsvCellEditor.OnLostFocus` |
| 新規 / タブ切替(Ctrl+Tab・Ctrl+1..9)/ タブを閉じる | 別文書 | `BeforeActiveChange` / `CloseActiveTab` が `AbortEdit`(コールバックを呼ばない) | `MainForm.cs` |
| F3 / Shift+F3 / Insert / Ctrl+Alt+P | **変えない** | 素通りするが本文に触らない | — |
| メニューやエディタを**クリック** | — | フォーカスが移る → `CancelEdit` | `CsvCellEditor.OnLostFocus` |
| バックアップ(hot exit)タイマー | **変えない** | ディスクへ書くだけ | `BackupCoordinator` |

**結論: 実機で踏む手順は見つかっていない。** したがってこの発声は
**「未確認(到達経路なし)」のまま L5 を終える。** 「確認済み」とも「網がある」とも書かないこと。

- この枝を守っているのは **L3 の 7 本だけ**であり、テストからしか踏めない
  (テスト本体のコメントにその旨が明記してある)。
- **「到達不能」自体もこのブランチの実測範囲を超えている。** `ConvertEols` が行列構造を変えない
  ことは T1 / T2 の **2 fixture 分だけが実測**で、一般には設計書 §4.4 の**論証**である
  (§8.9 が「§4.4 の全体が実測になったわけではない」と釘を刺している)。
- **将来 F2 編集中に本文を変える配線が 1 本増えたら、この項目は実機で踏めるようになる。**
  そのときは本項目を通常のチェック項目へ昇格させること。
- 実施者が上の表に無い到達手順を思いついたら**試して記録する**。踏めたなら
  逐語(`本文が変わったため確定できません。入力は破棄しました`)と、本文が 1 文字も
  変わっていないことを確認する。

### 項目 7 — 退行なし: 本文を変えずに F2 → Enter(通常の主経路)

**自動テストが届かない範囲**: 本文と発声は L3 で固定済み(`BeginEdit_ThenCommit_...`)。
**実機で見るのは、新しい同一性検証が通常操作を誤って拒否しないこと。**
guard が誤っていれば、**普通にセルを編集しただけで
`本文が変わったため確定できません。入力は破棄しました` が読まれて入力が捨てられる。**
これは実運用で最も痛い失敗様式であり、実機で最も早く出る。

| # | 手順 |
|---|---|
| 1 | 任意の CSV(`mix1b.csv` の続きでよい)で CSV モードに入る |
| 2 | **改行を含まないセル**(例 3 行 3 列 = `t2`)で F2 → `AAA` → Enter |
| 3 | **セル内改行を持つセル**(2 行 2 列)で F2 → 中身を変えずに **Enter**(no-op 確定) |
| 4 | 続けて 2 〜 3 セルを編集して Enter を繰り返す |

| 確認 | 期待 | 判定 |
|---|---|---|
| 発声(手順 2) | `AAA 3行3列`。**`本文が変わったため確定できません` は読まれない** | |
| 発声(手順 3) | `制御文字を含みます: x y 2行2列`(値は変わらない)。**拒否されない** | |
| 本文(手順 3 のあと・**目視**) | 2 行 2 列がまだ **2 表示行**にまたがる(セル内改行が失われていない) | |
| 本文 | 各回、狙ったセルだけが変わる | |
| テンポ | 連続確定で発声が詰まったり前の発話が残ったりしない(§1.1 の throttle) | |

> 手順 3 は **EOL 正規化を同一性検証から外す変異(m5)を実機で踏む形**でもある。
> 正規化が効いていなければ、**セル内改行を持つセルは何もしていないのに必ず拒否される**。
>
> **もう 1 つ、手順 3 でしか踏めない経路がある**: `CsvCellEditor.Begin` は
> `TextBox.Text = field.Value`(セル内改行は **LF 単独**)で初期値を入れ、`Commit` は
> `TextBox.Text` を**読み戻す**。この往復は L3 が一度も通っていない(テストは `Text` を
> 直接上書きしてから `Commit` する)。ネイティブ EDIT コントロールが LF 単独をどう保持するかは
> 実機でしか判らないので、**オーバーレイに 2 行で表示されるか**と
> **確定後に改行が残るか**を必ず記録すること。
