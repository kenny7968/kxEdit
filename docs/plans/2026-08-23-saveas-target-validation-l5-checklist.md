## なぜ L5 が必須か

SR 経路(`kxEdit.Accessibility` / `EditorControl` の UIA 部 / App の Speech 系)には**触れていない**。
それでも必須とするのは次の 3 つの理由による(CLAUDE.md §5「迷ったら必要に倒す」)。

1. **テキストボックス直入力が SR ユーザーの主経路**であり(A-7 の再現手順がそう書いている)、
   その経路に「警告 → ダイアログ再表示」というフォーカス遷移が新しく入った。
   再表示のたびにフォーカスがどこへ行くかは実機でしか判らない。
2. **⑥ は本ブランチで唯一、自動テストが原理的に届かない production 行の網**である
   (設計書 §10.9)。`SaveAsDialog.OverwritePrompt = false` は `Form` 上の行で `tests/` からの
   参照がゼロのため、消しても全テストが緑のまま通る。
3. **① の「MessageBox がどのボタンにフォーカスを置くか」は実機でしか見えない**(申し送り S-12)。
   `defaultCancel: true` が seam に渡っていることは L3 で pin したが、WinForms が実際に
   キャンセル側を初期フォーカスにするかは GUI を出さないと確認できない。
   ここが OK 側だと、主経路の打鍵パターン(打つ → Enter → 確認が開く → 反射的な 2 回目の Enter)
   そのもので上書き確認が無力化される。

**各項目の「自動テストが届かない範囲」は項目ごとに明記した。** 該当が無い項目は
「L3 で pin 済み・実機は聞こえ方の確認」と書いてある。

## 実施前の準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動しておく(発声の確認が目的なので、スピーチビューアーだけに頼らない)。
3. 作業用フォルダー `<任意のフォルダー>` を 1 つ作り、その中に既存ファイルを 2 つ置く。
   - `existing.txt` … 中身は `OLD` の 1 行。**上書きされていないことを本文で確認するために使う**。
   - `other.txt` … 中身は任意。③ で「別タブが開いているファイル」として使う。
4. ⑤ 用に、絵文字(例 `😀`)を含む本文をコピーできるようにしておく。
5. ⑧ 用に [ツール]>[設定] で **バックアップ有効**・**「起動時に前回開いていたファイルを開く」ON** に

## ① A-7 (a) 主経路 — 直入力した既存ファイル名で上書き確認が読まれ、既定が「キャンセル」

**これが本ブランチの中核。** 修正前は、テキストボックスにファイル名を打って OK を押すと
**無確認で上書き**されていた(`参照` ボタン経由だけが Windows 純正の確認を出していた)。
「主経路だけが無確認」という非対称そのものが A-7 (a) の実体である。

**自動テストが届かない範囲**: MessageBox の**初期フォーカスがどのボタンか**(S-12)。
`defaultCancel: true` が渡っていることは L3 の `FakePrompt.OkCancelCalls` で pin 済みだが、
WinForms がそれを実際にどう反映するかは実機でしか見えない。

**前提/準備**

- kxEdit を起動し、無題タブに `NEW` と入力する(保存先と中身を区別するため)。

**操作手順**

1. **Ctrl+Shift+S**(または [ファイル]>[名前を付けて保存])でダイアログを開く。
2. 「ファイル名」テキストボックスに **`<任意のフォルダー>\existing.txt`** を**キーボードで打ち込む**
   (`参照` ボタンは使わない)。
3. **Enter**(= OK)を押す。
4. 確認ダイアログが開いたら、**まず何も押さずに聞く**。NVDA が読む「フォーカスされているボタン」を
   メモする。
5. **Tab / Shift+Tab でボタンを行き来**して、OK とキャンセルの 2 つがあることを確認する。
6. **Esc** で確認を閉じ、続いて再表示された SaveAs ダイアログも **Esc** で閉じる。

**期待される読み上げ・挙動**

- 手順 3 の直後に確認ダイアログが開き、NVDA が
  タイトル **「上書きの確認」** と本文
  **「同じ名前のファイルが既に存在します。上書きしますか? 保存先: `<任意のフォルダー>\existing.txt`」**
  を読む。
- **問いが先・パスが後**の順で読まれる(パスが先頭だと、何を聞かれているかが最後まで判らない)。
- **初期フォーカスが「キャンセル」ボタンにある**(NVDA が「キャンセル ボタン」と読む)。
  **ここが「OK ボタン」なら FAIL。**
- Esc で閉じた後、`existing.txt` の中身が `OLD` のままである。

**参考(任意・S-12 の記述を事実に直すため)**: メモ帳など Windows 純正アプリの
「名前を付けて保存」で既存ファイルを選び、純正の上書き確認がどちらのボタンを既定にしているかも
見ておく。設計書 S-12 は起票時に「純正は『いいえ』が既定」と書いたが**未検証**で、
証拠はむしろ `Yes` を指している。判ったことを備考へ書けば S-12 を事実に直せる。

## ④ Ctrl+S 側の重複タブガード(Task 6b)と、S-10「黙って終了が中止される」の観測

③ は重複タブが「生まれる」経路を塞ぐが、「**既にある**」状態は塞がない。
バックアップ復元は同じ `OriginalPath` を持つレコードをパス重複排除なしで全件復元するので、
**既定構成(復元 OFF)でも同一パスの 2 タブが並ぶ**(申し送り S-9)。
Task 6b はその状態での Ctrl+S を止める。

**あわせて申し送り S-10 を実機で観測する。** 保存がこのガードで止まると、
クローズ/終了は**中止されるのに「閉じなかった」ことを誰も言わない**。読まれるのは
「**保存**が失敗した」であって「**終了を取りやめた**」ではない。現場は 2 箇所
(`MainForm.OnFormClosing` = ウィンドウの × / Alt+F4、`CloseActiveTab` = Ctrl+W)。

**自動テストが届かない範囲**: 「何も言われないこと」自体。無発声は L3 では表現できない。

**前提/準備 — 同一パスの 2 タブを作る**

1. [ツール]>[設定] で **バックアップ有効**・**間隔 30 秒**・
   **「起動時に前回開いていたファイルを開く」OFF**(既定)にする。
2. `<任意のフォルダー>\dup.txt` を作って開き、`AAA` と入力する。30 秒待って
   `%APPDATA%\kxEdit\backups\session-*\` に `.json` ができることを確認する。
3. **タスクマネージャーで強制終了**する。
4. 再起動する。復元ダイアログが出たら **「あとで(&L)」** を選ぶ(レコードは据え置かれる)。
5. もう一度 `dup.txt` を開き、`BBB` と入力する。30 秒待つ → **強制終了**。
6. 再起動する。復元ダイアログに **`dup.txt` が 2 件**並ぶので、**両方にチェックを入れて
   「選択を復元(&R)」**を押す。→ **同じパスのタブが 2 枚**開く。

> 2 件並ばない場合は手順 2〜5 をもう一度繰り返す。バックアップ間隔を待たずに強制終了すると
> レコードが書かれていない。

**操作手順**

1. 2 枚のタブそれぞれで **Ctrl+S** を押す。**片方は保存が通り、もう片方でエラーが出る**
   (先に生まれたタブが保存権を持つ)。エラーが出る方を以後「**止まるタブ**」と呼ぶ。
2. エラーの読み上げを聞く。OK で閉じる。
3. **止まるタブをアクティブにして Ctrl+W。** 未保存確認で **「はい」(保存する)** を選ぶ。
   その後の読み上げと画面を観察する。
4. 止まるタブを未保存のまま、**ウィンドウの × / Alt+F4** でアプリを終了しようとする。
   未保存確認で **「はい」** を選ぶ。その後の読み上げと画面を観察する。
5. 最後に、止まるタブを Ctrl+W → **「いいえ」(破棄)** で閉じ、アプリを終了できることを確認する。

**期待される読み上げ・挙動**

- 手順 1 で、NVDA がタイトル **「エラー」** と本文
  **「別のタブが同じファイルを開いています。このまま上書きすると、もう一方のタブの内容が失われます。
  「名前を付けて保存」で別の名前を指定するか、もう一方のタブを閉じてから保存してください: …」**
  を読む。③ の文言と**冒頭で区別できる**こと(③ は「このファイルは別のタブで…」)。
- 手順 1 でエラーが出た側のタブは**保存されない**が、`dup.txt` の中身も壊れない。
- 手順 3 で、エラーの後 **タブが黙って残る**(Ctrl+W が効かなかったことを何も言わない)。
- 手順 4 で、エラーの後 **アプリが終了しない**(終了を取りやめたことを何も言わない)。
- 手順 5 で、破棄すれば閉じられる = **無断喪失は起きていない**。

> **判定の注意**: 手順 3 / 4 の「何も言わない」は **S-10 として既知**であり、
> **本項目の FAIL ではない**(Task 6b が作った挙動でもなく、`SaveDocument` が false を返す
> 既存経路すべてに共通する)。ここで確かめたいのは「**実機で聞いたときにどれくらい迷子になるか**」で、
> 体感を備考に書けば S-10 の優先度を決められる。**FAIL にするのは、エラー自体が読まれないか、
> 手順 1 でエラーが出ずに片方の内容が消えた場合。**

## ⑤ Task 8 — 文字コード劣化警告を断るとダイアログへ戻る / 断った次の周回で上書き確認がもう一度出る

前半は Task 8 が入れた挙動(警告のキャンセルで中止せず再表示)。
**後半は自動テストが原理的に書けない**(設計書 §10.12): `FakePrompt.OkCancelResult` は
**すべての `OkCancel` に同じ答を返す単一の bool** なので、「上書きは承諾したが文字コード警告は
キャンセルする」という状況をテストで表現できない。**⑤ の後半が唯一の網である。**

**前提/準備**

- ① の `existing.txt`(中身 `OLD`)を用意しておく。
- 無題タブに **絵文字を含む本文**(例 `こんにちは😀`)を入力する。
  絵文字は Shift_JIS で表せないので劣化警告の対象になる。

**操作手順(前半 — 再表示)**

1. Ctrl+Shift+S。ファイル名に **新しい名前** `<任意のフォルダー>\enc.txt` を打つ。
2. 「文字コード」コンボボックスで **Shift_JIS** を選ぶ。Enter(OK)。
3. 劣化警告が出たら、**まず初期フォーカスがどちらのボタンにあるかを NVDA で確認してから**
   「キャンセル」を選ぶ。
4. 再表示されたダイアログで、文字コードを **UTF-8** に戻して Enter。

**操作手順(後半 — 上書き承諾の持ち越しが無いこと)**

5. Ctrl+Shift+S。ファイル名に **`<任意のフォルダー>\existing.txt`**(**既存**)を打つ。
6. 文字コードを **Shift_JIS** にして Enter。
7. **上書き確認が出るので「OK」で承諾する。**
8. 続いて劣化警告が出るので **「キャンセル」** を選ぶ。
9. 再表示されたダイアログで、**何も変えずにそのまま Enter**。
10. ここで何が起きるかを観察する。

**期待される読み上げ・挙動**

- **手順 3 で、劣化警告の初期フォーカスが「キャンセル」側にある**(S-12・Task 8 のレビューで
  上書き確認と対称にした)。ここが OK 側だと、Enter を押しっぱなしにしたとき
  **警告が読み上げられる前に確定して文字が `?` に置換される** — 知覚されない警告は警告ではない。
  「直前に自分でその文字コードを選んだのだから確認は軽くてよい」という理屈は成り立たない:
  コンボの初期値は開いた文書の文字コード由来なので、Shift_JIS で読み込んだ文書に絵文字を
  貼れば、文字コードに一度も触れずにこの警告に到達する。
  なお `defaultCancel` が seam に渡っていることは自動テストで pin 済みで、
  **実機でしか見えないのは「MessageBox が実際にどのボタンへフォーカスを置くか」だけ**。
- 手順 3 の後、**SaveAs ダイアログが再表示される**(中止されない)。文字コードのコンボボックスは
  そのダイアログの中にあるので、そこで選び直せる。
- 手順 4 で保存が成功し、`enc.txt` に絵文字が正しく入る(`?` になっていない)。
- **手順 10 で、上書き確認が再び読まれる**(手順 7 の承諾は持ち越されない)。
  これは**意図した挙動**であり FAIL ではない(設計書 §10.11)。承諾は「その周回で選ばれた
  保存先」への答であり、再表示ではパスを打ち替えられる以上、持ち越すと
  「`a.txt` を上書きしていい」という承諾が打ち替え後の `b.txt` の上書きを黙って許してしまう。
- 一連の操作を通じて `existing.txt` の中身が **`OLD` のまま**である。

**結果**: ☐ PASS ☐ FAIL — 手順 3 の初期フォーカス: ☐ キャンセル ☐ OK /
手順 10 で上書き確認は出たか: ☐ 出た ☐ 出なかった / 備考:

## ⑥ `参照` 経由でも確認は 1 回だけ(**自動テストが原理的に届かない唯一の項目**)

設計書 §4.5 は確認点を 1 箇所に集約するため `SaveAsDialog.OverwritePrompt = false` を入れた。
**この行は自動テストで kill できない**(§10.9): `SaveAsDialog` は `Form` で `tests/` からの参照が
ゼロなので、行を消しても全テストが緑のまま通る。**本項目が唯一の網であり、
L5 を実施するまでこの行は無保護である。**

**前提/準備**

- 無題タブに `NEW` と入力する。
- `existing.txt` の中身が `OLD` であることを確認しておく。

**操作手順**

1. Ctrl+Shift+S でダイアログを開く。
2. **Tab で `参照(&B)...` ボタンへ移動して Enter**(または Alt+B)。
3. Windows 純正の「名前を付けて保存」が開くので、**`existing.txt` を選んで「保存」** を押す。
4. **ここで確認が出るかどうかを聞く。**
5. kxEdit の SaveAs ダイアログに戻ってファイル名欄が埋まったら、**Enter**(OK)。
6. **ここで確認が出るかどうかを聞き**、**「キャンセル」** を選ぶ。
7. Esc でダイアログを閉じる。

**期待される読み上げ・挙動**

- **手順 4 では確認が出ない**(純正 `SaveFileDialog` の `OverwritePrompt` を切ってある)。
  そのまま kxEdit のダイアログへ戻る。
- **手順 6 で確認が 1 回だけ出る**(タイトル「上書きの確認」)。

## ⑨ A-4 — ネットワーク共有へ**新規**ファイルを保存できる(**実共有が無ければスキップ可**)

修正前は、到達性の判定に `File.Exists` をそのまま使っていたため、**まだ存在しない**新規パスは

> **実施可否**: この項目は **書き込み可能な実 SMB 共有(`\\server\share` またはマップド

> **その場合は「スキップ」に印を付けて先へ進んでよく、マージのブロッカーにはしない。**
> 本番プローブの意味論(`Reachable = FileExists || 親フォルダーが存在`)は L3 の
> `FileReachabilityProbeTests`(実一時ディレクトリを使う)が pin しており、A-4 の核である

**前提/準備**

- 書き込み可能な共有 `\\<サーバー>\<共有名>` を用意する(マップドドライブでもよい)。

**操作手順**

1. Ctrl+Shift+S。ファイル名に **`\\<サーバー>\<共有名>\netnew.txt`**(**まだ存在しない名前**)を
