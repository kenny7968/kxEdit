## なぜ L5 が必須か

SR 経路(App の Speech 系 = `SearchController.Announce` → `IAnnouncer.Say`)に**触れている**。
CLAUDE.md §5 の「App の Speech 系に触れる変更は必須」に直接該当する。

1. **置換位置そのものが変わった。** A-14 は「別の出現が置換される」不具合で、
   SR ユーザーには**置換位置が見えない**。自動テストは本文と選択と発声文言を固定できるが、
   「置換された場所を SR がどう読むか / ユーザーが位置を見失わないか」は実機でしか判らない。
2. **`ReplaceOne` から出る発声が 2 種類増えた。**「選択範囲がありません」と
   「選択範囲が変わりました。選択し直してください」。どちらも `ReplaceAll` の既存文言の
   再利用だが、**単発置換の文脈で出るのは初めて**。既存の別文言と取り違えないかを確認する。
3. **範囲外で止まったときのフィードバックが弱い可能性がある**(実装者の申し送り)。
   スコープ外のヒットが選択されている状態で「置換」を押すと「これ以上見つかりません」と
   発声するが、ユーザーの目 / SR には「いま選択されている語」がある。
   **「なぜ置換されないのか」が伝わるか**は実機判定でしか答えが出ない。
4. **件数表示と実際の到達範囲が食い違う受容済みの非一貫がある**(設計書 §6)。
   「選択範囲のみ」ON でも `UpdateCount` は全文を数えるので、「12 件」と表示されたまま
   置換が範囲末で止まる。**SR ユーザーがこれを不具合と受け取らないか**を確認する。

**各項目に「自動テストが届かない範囲」を明記した。**

## 実施前の準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動し、**スピーチビューアー**(NVDA メニュー → ツール → スピーチビューアー)を開く。
   発話の逐語確認はスピーチビューアーで行い、音声の質・速度・割り込みは耳で確認する。
3. 作業用フォルダーに次のファイルを置く。**CRLF のファイルは kxEdit 以外で作ること**
   (kxEdit で作ると保存時に EOL が統一される)。

   | ファイル | 内容 | 用途 |
   |---|---|---|
   | `crlf.txt` | `abc` / `def` / `ghi` の 3 行。**改行は CRLF**。メモ帳で作成 | ①②③ |
   | `scope.txt` | `abc abc abc` の 1 行(前後に非ヒット部を持たせたい場合は `zz abc abc zz`) | ④〜⑦ |

   PowerShell での作成例(UTF-8 を明示すること):

   ```powershell
   "abc`r`ndef`r`nghi" | Out-File -Encoding utf8 -NoNewline crlf.txt
   "abc abc abc"       | Out-File -Encoding utf8 -NoNewline scope.txt
   ```

4. **windows-mcp でのキー送出は他ウィンドウへ漏れる**ことがある(既知)。
   ダイアログのボタン操作は可能なら UIA の InvokePattern を使う。

## チェック項目

判定は **PASS / FAIL / N/A** を記入し、FAIL は「聞こえた文言」または「見えた状態」を逐語で残す。

### ① CRLF 文書で正規表現 `\n` を単発置換する(A-14 の本丸)

**自動テストが届かない範囲**: 本文と選択と発声文言は L3 で pin 済み。
**実機で見るのは、置換された場所を SR がどう読むか**。

1. `crlf.txt` を開く。
2. Ctrl+H で置換ダイアログを開き、**正規表現を ON**、検索語に `\n`、置換後に `X` を入れる。
3. 「次を検索」を 1 回押す。
4. 「置換」を 1 回押す。

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文 | `abc` の直後の LF だけが `X` になり、**2 つ目の改行は無傷**(`abc\rXdef\r\nghi`) | |
| 発声 | 「置換しました。2 件中 1 件目」相当が **1 回だけ**読まれる | |
| 位置 | 置換後に選択が移った先を SR が読み、ユーザーが現在位置を見失わない | |

> 修正前はここで **2 つ目の改行が置換されていた**(A-14)。

### ② CRLF 文書で正規表現 `\r` を F3 で送る(A-14 の裏側)

**自動テストが届かない範囲**: 前進すること自体は L3 で pin 済み。
**実機で見るのは、ゼロ幅選択になる位置で SR が何を読むか**。

1. `crlf.txt` を開き、Ctrl+F で検索ダイアログ、**正規表現 ON**、検索語に `\r`。
2. F3 を 3 回押す。

| 確認 | 期待 | 判定 |
|---|---|---|
| 前進 | 1 回目・2 回目で**別の行**へ進む(同じ位置に留まらない) | |
| 3 回目 | 「これ以上見つかりません」が読まれる | |
| 発声 | ゼロ幅選択の位置でも無音にならず、行の内容か位置が読まれる | |

> 修正前は **1 回目と 2 回目が同じ位置**に留まっていた。

### ③ CRLF 文書で正規表現 `\r` を単発置換する

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文 | CR だけが `X` になり **LF が残る**(`abcX\ndef`)。行数が減らない | |
| 発声 | 「置換しました。…」が 1 回だけ | |

### ④ 「選択範囲のみ」ON で範囲内を置換する(T-3・正常系)

**自動テストが届かない範囲**: 本文と発声は L3 で pin 済み。
**実機で見るのは、範囲内で連打したときの読み上げのテンポと割り込み**。

1. `scope.txt`(`abc abc abc`)を開く。
2. 中央の `abc`(4 文字目から 3 文字)を選択する。
3. Ctrl+H → 「選択範囲のみ」を ON にする。検索語 `abc`、置換後 `X`。
4. 「置換」を 1 回押す。

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文 | `abc X abc` —— **前後の 2 件は残る** | |
| 発声 | 「置換しました。これ以上見つかりません」が 1 回だけ | |
| 件数表示 | ダイアログのステータスは**全文基準のまま**(受容済みの非一貫)。ここで混乱しないか | |

> 修正前は範囲外も置換対象だった。

### ⑤ 「選択範囲のみ」ON でスコープ外にキャレットを置いて置換する(T-3 の本丸)

**自動テストが届かない範囲**: 本文不変と発声文言は L3 で pin 済み。
**実機で見るのは、③ の申し送り —— 「なぜ置換されないのか」がユーザーに伝わるか**。

1. ④ の続き、または `scope.txt` を開き直して中央を捕捉。
2. キャレット(または選択)をスコープの**外**、3 つ目の `abc` へ動かす。
3. 「置換」を押す。

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文 | **一文字も変わらない** | |
| 発声 | 「これ以上見つかりません」が 1 回だけ | |
| 伝わるか | 選択されている語があるのに置換されない理由が、SR ユーザーに伝わるか **← 主観判定・要記録** | |

> ここが FAIL(伝わらない)なら、新しい発声文言の追加を次のブランチで検討する。
> 本ブランチでは「新規文言を追加しない」制約で実装しているため、判断材料を集めるのが目的。

### ⑥ 「選択範囲のみ」ON でスコープ未捕捉のまま置換する

1. `scope.txt` を開く。**何も選択せずに** Ctrl+H → 「選択範囲のみ」を ON。
2. 検索語 `abc`、置換後 `X` を入れて「置換」を押す。

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文 | 変わらない | |
| 発声 | **「選択範囲がありません」** が 1 回だけ | |
| 取り違え | 次の ⑦ の文言と**明確に区別できる**か | |

### ⑦ スコープ捕捉後に本文を編集してから置換する(陳腐化)

1. `scope.txt` を開き、中央の `abc` を選択して「選択範囲のみ」を ON。
2. **文書の先頭に何か文字を入力する**(捕捉位置が別の中身を指すようになる)。
3. 「置換」を押す。

| 確認 | 期待 | 判定 |
|---|---|---|
| 本文 | 手入力した文字以外は**一文字も変わらない** | |
| 発声 | **「選択範囲が変わりました。選択し直してください」** が 1 回だけ | |
| 取り違え | ⑥ の「選択範囲がありません」と**明確に区別できる**か | |
| 復帰 | 選択し直して ON にし直すと ④ が通ることを確認 | |

### ⑧ 回帰: 通常文書(LF のみ)の単発置換が従来どおり

**自動テストが届かない範囲**: なし(L3 で全面 pin 済み)。**実機は聞こえ方の確認のみ**。

1. 適当な LF 文書で `abc` を `X` に単発置換し、連打して最後まで送る。

| 確認 | 期待 | 判定 |
|---|---|---|
| 発声 | 「置換しました。N 件中 M 件目」→ 最後に「置換しました。これ以上見つかりません」 | |
| テンポ | 連打時に発声が詰まったり前の発話が残ったりしない | |
