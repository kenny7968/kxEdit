## 0. 準備

### 0.1 なぜ目視が要るか(自動テストで届く範囲/届かない範囲)

**自動テストで既に固定されている事実(L5 で確かめ直さない)**

| 事実 | 網 |
|---|---|
| 4 テーマの選択背景色・選択文字色の値そのもの | L1 `AppearanceThemeTests.Selection_colors_are_defined_per_theme` |
| 標準テーマだけが選択文字色を持たないこと | 同 `Only_non_default_themes_specify_selection_foreground` |
| 選択文字色ありのとき本文 op が選択境界で分割されること(部分 / 行頭 / 行末 / 行またぎ / 折り返し / 空選択) | L1 `FrameBuilderSelectionForeTests` |
| 選択文字色が null(標準テーマ相当)なら本文 op が 1 本のままであること | 同 `Null_selection_fore_keeps_single_body_run_even_when_selected` |
| サロゲートペアを割る選択でも文字が欠落・重複しないこと | 同 `Selection_inside_surrogate_pair_preserves_all_text` |
| `ApplyAppearance` 後の選択背景が 4 テーマでテーマ表どおりになること | L2 `EditorControlSelectionColorTests.SelectionBack_follows_theme` |
| IME 変換対象節の文字色が 4 テーマとも黒のままであること(#74 からの挙動不変) | L2 `ImeOverlayColorTests.OverlayTargetForeColor_StaysBlackForAllThemes` |

**自動テストでは届かない範囲(ここを目視で見る)**

- 実際に**読めるか**(コントラスト)。テストが言えるのは「期待した色の op が出た」までで、
  可読性は判定できない。
- **眩しすぎないか**。黒地テーマの選択背景に明るい黄 / 緑を全面に敷くのは本件で初めて入る見た目で、
  弱視ユーザー向けテーマの目的を損なわないかは目視でしか判定できない(項目 9)。
- **選択矩形と文字の位置が一致しているか**。本文を分割描画するため、非 ASCII 混在行で理論上
  1px 程度のずれが起こりうる(設計書 §8 の申し送り)。
- **文字が欠けたり消えたりしていないか**。分割された run の幅は prefix 計測の差分であって
  run 単独を測った幅ではないため、実描画幅が差分を上回ると右端が削れうる
  (2026-09-14 のレビュー指摘。描画側で水平クリップを外して対処済みだが、**対処が効いているかは
  目視でしか確認できない**)。加えて、**アラビア文字やタイ文字のように 1 語がまとまって字形を
  変える文字**では、選択境界で run が割れると字形が変わりうる(分割方式に内在する制約)。
- 実 GDI での描画結果(テストは `PaintOp` の並びまでしか見ていない)。

### 0.2 手順

1. `feature/selection-theme-color` をビルドして起動する(Release 推奨)。
2. テーマの切り替え導線: `Alt` → `O`(オプション)→ `P`(設定)→ **「表示」タブ** →
   **「配色(&C):」** のコンボ。選択肢は「標準（白地に黒）」「黒地に白」「黒地に黄」「黒地に緑」。
3. 検証用の本文を用意する。**例文はここに書いたものを使うこと**(後述の ⚠ 参照):

   ```
   abcdefghij klmnopqrst
   これは日本語の行です。ABC と混在しています。
   1234567890 1234567890
   ```

4. 選択の作り方(いずれも使う):
   - **行の途中だけ**: 行の中ほどでマウスドラッグ、または `Shift` + `→` を数回。
     **行頭でも行末でもない**位置から始めて、**行末に届かない**位置で止めること。
   - **行頭から**: `Home` → `Shift` + `→` を数回。
   - **行末まで**: 行の中ほどにキャレットを置き `Shift` + `End`。
   - **複数行にまたがる**: `Shift` + `↓` を数回、または `Ctrl` + `A`(全選択)。

> ## ⚠ 空振り・取り違えを防ぐための 4 点
>
> **(a) 「行の途中だけ」の選択を必ず 1 回は作ること。**
> 全選択(`Ctrl` + `A`)だけで判定すると、**選択されていない部分の色**が画面に無いため
> 「分割が効いているか」を見ていないことになる。分割の失敗(選択外まで黒くなる / 選択内が
> 本文色のまま)は、**prefix と suffix が両方見えている状態**でしか目視で捕まらない。
>
> **(b) 「対象節が黒い」は FAIL ではない。**
> IME 変換中の**対象節**(太字 + 選択背景)の文字色は #74 で黒に固定してあり、本件でも
> 4 テーマとも結果は黒のままである(設計書 §5.3・**意図した挙動不変**)。
> FAIL なのは、対象節が**選択背景と同系色になって読めない**場合だけ。
>
> **(c) 空白可視化グリフ・CSV のセルハイライトは選択色に連動しない(仕様)。**
> 選択範囲の中の空白グリフ(`·` / `→`)が選択文字色にならなくても **FAIL ではない**
> (設計書 §8 の申し送り。スコープ外)。見るのは**本文の文字**の色。
>
> **(d) 標準テーマは「何も変わっていないこと」を見る。**
> 標準テーマの選択は従来どおり**水色地に黒**である。ここが「白地に黒の反転」などに
> **変わっていたら FAIL**(標準テーマは描画完全不変が本件の不変条件)。

## 2. FAIL 時の扱い

- **選択部分が依然として水色地** → テーマ表から `ViewportStyle` への配線漏れ。
  項目 18(起動直後)で出たのか、項目 3/5/7(設定ダイアログ経由)で出たのかを必ず区別して記録する。
- **選択部分の背景は変わったが文字が本文色のまま**(黒地に白で「白地に白」)→ 本文 op の分割が
  効いていない。`ViewportStyle.SelectionFore` が null のまま渡っている疑い。
- **選択矩形と文字の範囲がずれる**(項目 10/11)→ 分割の X / 幅の算出。**ずれた文字列と選択位置を
  逐語で記録する**(何文字目から何文字目を選択したか)。1px 程度のにじみは申し送りの許容範囲、
  **1 文字分ずれていたらバグ**。
- **項目 9 が FAIL(眩しい)** → 設計の想定内。§1.5 の対処(白固定への切り替え)を行い、
  マージはブロックしない。
- **項目 15/16 が FAIL** → #74 の退行。**マージしない**。
