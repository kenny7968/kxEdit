**自動テストでは届かない範囲(ここを目視で見る)**

- **眩しすぎないか**。黒地テーマの選択背景に明るい白 / 黄 / 緑を全面に敷くのは本件で初めて入る
  見た目で、弱視ユーザー向けテーマの目的を損なわないかは目視でしか判定できない(項目 9)。
  コントラスト比の自動テストは「文字と背景が見分けられるか」しか言えず、**面の明るさ**は見ていない。
- **PaintOp から実 GDI までの間**。自動テストは `PaintOp` の並びまでしか見ていない。
  矩形と run の一致は PaintOp レベルで厳密に固定済みなので、残る隙間は「PaintOp を
  `TextRenderer.DrawText` に流したときに見えるもの」だけ(項目 10・11・11b)。
- **文字が欠けたり消えたりしていないか**。分割された run の幅は prefix 計測の差分であって
  run 単独を測った幅ではないため、実描画幅が差分を上回ると右端が削れうる。
  **advance 0 のコードポイント(結合文字)だけが区間に入ると幅が 0 になり、その run は一切
  描かれない**。描画側で水平クリップを外して対処済みだが、**効いているかは目視でしか確認できない**
  (項目 11b)。
- **アラビア文字やタイ文字のように 1 語がまとまって字形を変える文字**では、選択境界で run が
  割れると字形が変わりうる(分割方式に内在する制約。スコープ外だが、見えたら記録する)。
- 実 IME(MS-IME 等)が作る**本物の節構成**での見え方(項目 15・16)。

### 0.2 ⚠ 水平クリップ解除について(標準テーマの「不変」の正確な意味)

本件では描画側で **DrawText の矩形幅を右端まで広げ、水平方向のクリップを外している**
(`EditorControl.Paint.cs` の `RenderFrame`)。これは `case PaintOpKind.DrawText:` **全体**に
効くので、分割された本文 run だけでなく**標準テーマの本文・行番号・空白可視化グリフにも効く**。

したがって「標準テーマは描画完全不変」(設計書 §5.2)の正確な意味は次のとおり:

- **`PaintOp` の並びは完全に不変**(自動テストが固定している)。
- **実際の画素は、従来 `MeasureText` の報告幅で右端が切れていた場合に切れなくなる**
  = はみ出しぶんが描かれるようになる。切れていなかった箇所は 1 画素も変わらない。

**標準テーマで「文字が少し広く見える / 右端のはみ出しが描かれている」のは FAIL ではない。**
FAIL なのは、標準テーマの**選択の色**が変わっている場合(水色地に黒 以外になっている場合)。

### 0.3 手順

1. `feature/selection-theme-color` をビルドして起動する(Release 推奨)。
2. **設定ダイアログの導線**(項目ごとに使うタブが違うので注意):
   - 開く: `Alt` → `O`(オプション)→ `P`(設定)
   - **「表示」タブ**: **「配色(&C):」**コンボ(選択肢は「標準（白地に黒）」「黒地に白」
     「黒地に黄」「黒地に緑」)/ **「行番号を表示する(&N)」**チェック /
     **「空白・改行文字を表示する(&B)」**チェック / **「フォント:」**行の変更ボタン(`&F`)
   - **「編集」タブ**: **「折り返し桁数(&K):」**(0 = 折り返さない)
3. 検証用の本文を用意する。**この 5 行をそのままコピーして貼り付けること**
   (4 行目・5 行目は特殊な文字を含み、手で入力できない):

   ```
   abcdefghij klmnopqrst
   これは日本語の行です。ABC と混在しています。
   1234567890 1234567890
   か゛ け゜ é 𠮷 が
   絵文字テスト 😀 の行 ABC
   ```

   - **4 行目**は先頭 3 つが**結合文字**(`か`+U+3099 / `け`+U+309A / `e`+U+0301 = 2 コード
     ポイントで 1 文字に見える)、`𠮷` が**サロゲートペア**、末尾の `が` は比較用の単一文字。
     **項目 11b はこの行で撃つ。**
   - **5 行目**の `😀` もサロゲートペア。**項目 11c はこの行で撃つ。**
   - 貼り付け後、4 行目の見た目が `が け° é 𠮷 が` のように**濁点・アクセントが前の文字に
     乗っている**ことを確認する(乗らずに別文字として並ぶフォントでもよいが、その場合は
     項目 11b の「結合列の内側」判定が変わるので実施記録に書く)。

4. 選択の作り方(いずれも使う):
   - **行の途中だけ**: 行の中ほどでマウスドラッグ、または `Shift` + `→` を数回。
     **行頭でも行末でもない**位置から始めて、**行末に届かない**位置で止めること。
   - **行頭から**: `Home` → `Shift` + `→` を数回。
   - **行末まで**: 行の中ほどにキャレットを置き `Shift` + `End`。
   - **複数行にまたがる**: `Shift` + `↓` を数回、または `Ctrl` + `A`(全選択)。

> ## ⚠ 空振り・取り違えを防ぐための 5 点
>
> **(a) 「行の途中だけ」の選択を必ず作ること。全選択だけで判定しない。**
> 全選択(`Ctrl` + `A`)だけで判定すると、**選択されていない部分の色**が画面に無いため
> 「分割が効いているか」を見ていないことになる。分割の失敗(選択外まで色が変わる / 選択内が
> 本文色のまま)は、**prefix と suffix が両方見えている状態**でしか目視で捕まらない。
>
> **(b) 項目 3 / 5 / 7 は必ず「2 行目(日本語混在行)」で撃つ。**
> 1 行目(ASCII のみ)では文字幅の計測が単純な足し算になり、**境界ずれが原理上起きない**。
> ASCII 行だけで撃つと「境界が 1 文字ずれない」を実質検査しないまま PASS になる。
>
> **(c) 「対象節が黒い」は FAIL ではない。ただし「対象節の背景が水色のまま」は FAIL。**
> IME 変換中の**対象節**の文字色は #74 で黒に固定してあり、本件でも 4 テーマとも結果は黒の
> まま(**意図した挙動不変**)。一方、対象節の**背景**は選択背景を流用しているので、黒地
> 3 テーマでは **水色 → 白 / 黄 / 緑** に変わる(本件の副作用)。詳細は §1.7。
>
> **(d) 空白可視化グリフ・CSV のセルハイライトは選択色に連動しない(仕様)。**
> 選択範囲の中の空白グリフ(`·` / `→`)が選択文字色にならなくても **FAIL ではない**
> (設計書 §8 の申し送り。スコープ外)。見るのは**本文の文字**の色。
> ただし「グリフが**見えている**こと」は項目 19 で確認する。
>
> **(e) 標準テーマは「選択の色が変わっていないこと」を見る。§0.2 も読むこと。**
> 標準テーマの選択は従来どおり**水色地に黒**。ここが「白地に黒の反転」などに変わっていたら FAIL。
> 判定は**期待欄に書いてある色と一致するか**だけで行う(main をビルドして見比べる必要はない)。
> 文字の右端のはみ出しが描かれるようになるのは §0.2 のとおり FAIL ではない。

### 1.7 IME の退行確認(#74 の成果が壊れていないこと)

| # | 操作 | 期待 | 判定 | 備考 |
|---|---|---|---|---|
| 15 | 黒地 3 テーマそれぞれで `きょうはいいてんきです` と入力し、**変換キーを押さない**(通常節のみ) | **テーマ前景色**(白 / 黄 / 緑)で読める(#74 の成果) | | |
| 16 | 同じ状態で `Space` 変換し、`←` / `→` で対象節を移動させて通常節と混在させる | 対象節の背景が**そのテーマの前景色(白 / 黄 / 緑)**になり、その上に**黒の太字**で読める。通常節はテーマ前景色。**両方同時に読める** | | |

> **(i) 対象節の「背景」も今回変わる。** 対象節の背景は選択背景を流用しているので、
> 黒地 3 テーマでは **水色 → 白 / 黄 / 緑** に変わる。
> - 白 / 黄 / 緑の地に黒の太字 = **期待どおり(PASS)**。
> - **水色のままなら FAIL**(テーマ連動が対象節の背景に届いていない)。
> - 文字が読めない(地と文字が同系色)なら FAIL。設計書 §4 の「副次的に
>   `OverlayTargetForeColor` の黒が全テーマで妥当なまま」という前提が崩れている。
>
> 標準テーマでは対象節の背景は**水色のまま**(変化なし)が期待値。
>
> **(ii) いま見ているのが kxEdit 自身の描画か確かめる。**
> kxEdit は IME 既定の合成ウィンドウを抑止して未確定文字列を自前描画している。何らかの理由で
> IME 側のウィンドウが出ていると、それはシステム色で描かれるため**黒地テーマでも読めてしまい、
> 修正が効いていなくても PASS になる**。
> **判別基準(#74 から更新)**: 変換したとき対象節に**そのテーマの前景色(白 / 黄 / 緑)の背景**が
> 付くなら、見ているのは kxEdit の overlay。#74 の旧基準「水色の背景が付く」は、本 PR で
> 選択背景がテーマ連動になったため**もう使えない**。
>
> **(iii) 1 文節に変換されると混在が作れない。**
> `←` / `→` を押しても対象節が移動しないなら、MS-IME が 1 文節にまとめている。その状態では
> **通常節と対象節が同時に出ない**ので、項目 16 を撃ったことにならない。
> **対象節が動かなかったら別の文で撃ち直すこと**(推奨: `あしたのかいぎはじゅうじからです`)。

## 2. FAIL 時の扱い

- **選択部分が依然として水色地** → テーマ表から `ViewportStyle` への配線漏れ。
  項目 18(起動直後)で出たのか、項目 3/5/7(設定ダイアログ経由)で出たのかを必ず区別して記録する。
- **選択部分の背景は変わったが文字が本文色のまま**(黒地に白で「白地に白」)→ 本文 op の分割が
  効いていない。ただしこの状態は L2 `ImeOverlayColorTests.OverlayTargetForeColor_StaysBlackForAllThemes`
  が先に赤くなるはずなので、**L5 まで到達しているなら自動テストの穴**でもある。両方報告する。
- **選択矩形と文字の範囲がずれる**(項目 10/11)→ 分割の X / 幅の算出。**ずれた文字列と選択位置を
  逐語で記録する**(何文字目から何文字目を選択したか)。1px 程度のにじみは申し送りの許容範囲、
  **1 文字分ずれていたらバグ**。
- **文字が消える・右端が削れる**(項目 11b/11c/19)→ 水平クリップ解除が効いていない。
  **どの文字が・どの選択位置で消えたか**を逐語で記録する。
- **項目 9 が FAIL(眩しい)** → §1.5 の切り分けを行い、**ユーザーに判断を仰ぐ**。
  白固定で解決するとは限らない(白は最も明るい)。**判断が出るまでマージしない**。
- **項目 15/16 が FAIL** → #74 の退行。**マージしない**。
