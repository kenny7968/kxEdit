# フェーズ 8: grep(perf-grep) 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** grep で、バイナリと一致しないファイルに対する無駄な処理(全文の文字コード判定・改行コード判定・行ごとの Substring・一致しないファイルの行分割)をなくす(P-8)。

**Architecture:**
- **NUL 判定を先に行う**: `GrepService.Search` の順序を `ReadAllBytes → ContainsNul → Detect` にする。
- **改行コード判定を省く**: `TextFileService` に、本文の文字列だけを返す internal の `DecodeTextOnly(byte[], int codePage)` を足す(`LineEndingDetector.Detect` と置換文字の走査をしない)。`DecodeBytes` と同じ復号の部品を共有する。
- **行ごとの Substring をやめる**: `TextSearcher` に internal の `FindFirst(ReadOnlySpan<char>)` を足し(`Regex.EnumerateMatches(ReadOnlySpan<char>)` の先頭)、`CollectLineHits` は行の span で照合する。一致した行だけ `LineText` の文字列を作る。
- **リテラル検索の全文プリフィルタ**: `UseRegex=false` のとき、同じ Regex の `IsMatch` を全文にかけ、false なら行分割を丸ごと省く。`RegexMatchTimeoutException` は握ってプリフィルタなしに戻る。テスト用に、プリフィルタを差し替えられる internal の `Search` オーバーロードを足す。

**Tech Stack:** C#(.NET 9)、System.Text.RegularExpressions、xUnit。

**Spec:** `docs/plans/2026-09-24-general-perf-improvements-design.md` §3・§13(以下「設計書」)

## Review Focus

- **途中の行に `^` / `$` を使う正規表現** — 1 行目・最終行だけでなく、途中の行でも行頭・行末として効くこと(span 化で意味が変わらないこと)。Task 3 の `Regex_line_anchors_match_middle_lines` で押さえる。
- **前の行の末尾・次の行の先頭を見る後読み・先読み**(例: `(?<=a)b` で、前の行が `a` で終わり、次の行が `b` で始まる) — 行の外を見ずに不一致になること(従来の Substring と同じ)。Task 3 の `Lookaround_does_not_see_across_line_boundary` で押さえる。
- **単語単位のリテラルが行頭・行末にある**(例: `TARGET` だけの行が `xTARGET` の行の次にある) — プリフィルタが全文の `\b` で偽陰性を出さないこと。Task 4 の同等性テスト(プリフィルタあり・なしの結果一致)で押さえる。
- **検索語に大文字小文字の変換で長さや表記が変わる非 ASCII(例: `ǅ`・`K`(ケルビン記号)・全角英字)を含む** — プリフィルタとの比較で `IndexOf` を使わないので、行単位照合と同じ結果になること。Task 4 の同等性テストの fixture に含める。
- **NUL が先頭 8000 バイトより後ろにだけあるファイル** — 従来どおりテキストとして照合されること(NUL 判定の窓を移動で変えないこと)。Task 2 の `Nul_beyond_sniff_window_is_scanned_as_text` で押さえる。

### 0.2 設計書からの精密化・逸脱

- **改行コード判定の省略は `DecodeTextOnly` という別経路にする**(設計書 §13.1-2「改行コード判定をしないデコードの経路を足す」の具体化)。`DecodeBytes` と共通の部品は `CreateDecoder(int codePage)` と `DecodeBody(...)` に切り出して共有する(同じ復号であることを構造で保証する)。置換文字の走査(`HadReplacementChar`)も grep では使わないので省く。
- **`DecodeTextOnly` は BOM を `HasBomFor(bytes, codePage)` で判定する**。現行の grep は `DecodeBytes(bytes, det.CodePage)`(強制コードページの経路)を呼んでおり、BOM はこの経路で `HasBomFor` から求めている。これと 1 バイトも違わないことを保つため、`det.HasBom` は使わない。
- **行の照合は `TextSearcher.FindFirst(ReadOnlySpan<char>)`**。`Regex.EnumerateMatches(ReadOnlySpan<char>)` の最初の要素を返す。`Regex.Match(line, 0)` と同じ入力・同じ開始位置なので同じ一致を返す(Task 3 で等価性テストを先に書いて確かめる)。
- **プリフィルタは `continue` で抜けない**。`if (プリフィルタが通す) CollectLineHits(...)` の形にする。`continue` だと、ループ末尾の進捗通知(64 ファイルごと)を飛ばしてしまい、進捗の通知回数が変わる(既存のバイナリ・巨大スキップの `continue` は従来の挙動なので変えない)。
- **プリフィルタの差し替え口**: `internal static GrepOutcome Search(GrepRequest, IProgress<GrepProgress>?, CancellationToken, Func<TextSearcher, string, bool> literalPrefilter)` を足す。public の `Search` は既定の `DefaultLiteralPrefilter` を渡す。`literalPrefilter` の `RegexMatchTimeoutException` は `Search` の側で握って「通す」に倒す(差し替え口から例外を注入してフォールバックを決定的に試せるようにするため。実時間のタイムアウトを起こすテストは作らない — リテラルのベクトル化走査は途中でタイムアウトを確かめないことがあり、揺れるため)。
- **プリフィルタが正しい(偽陰性を出さない)理由**(レビューで確認する論証): リテラル(`Regex.Escape`)に対し、ある行 `[pos, eol)` の位置 i で一致するなら、全文の位置 pos+i でも同じ文字列が一致する(大小無視の比較は文字ごとで文脈に依らない)。単語単位の `\b` は、行頭では「前が入力の外 = 非単語」、全文では「前が `\r`・`\n`・入力の外 = 非単語」で同じ判定になる(行末も同様)。検索語が `\r`・`\n` を含む場合は、行単位ではそもそも一致しないので、プリフィルタの結果によらず結果は同じ。

```csharp
    [Fact]
    public void Nul_beyond_sniff_window_is_scanned_as_text()
    {
        using var t = new TempDir();
        // NUL 判定の窓は先頭 8000 バイト。窓の外の NUL だけならテキストとして照合する(従来どおり)。
        var bytes = new List<byte>(Encoding.ASCII.GetBytes("TARGET\n"));
        while (bytes.Count < 8000)
            bytes.Add((byte)'x');
        bytes.Add(0x00);
        t.Write("late-nul.txt", bytes.ToArray());

        var outcome = GrepService.Search(Req(t.Root, "TARGET"));
        var hit = Assert.Single(outcome.Hits);
        Assert.Equal(1, hit.LineNumber);
    }

    [Fact]
    public void Nul_at_last_byte_of_sniff_window_is_binary()
    {
        using var t = new TempDir();
        // 窓の最後のバイト(添字 7999)の NUL はバイナリ扱い(境界の固定)。
        var bytes = new List<byte>(Encoding.ASCII.GetBytes("TARGET\n"));
        while (bytes.Count < 7999)
            bytes.Add((byte)'x');
```

```csharp
    public static LoadedDocument DecodeBytes(byte[] bytes, int? forcedCodePage = null)
    {
        EncodingCatalog.EnsureRegistered();

        DetectedEncoding det = forcedCodePage is int cp
            ? new DetectedEncoding(cp, HasBomFor(bytes, cp))
            : EncodingDetector.Detect(bytes);

        Encoding enc = EncodingCatalog.Get(det.CodePage);
        string text = DecodeBody(bytes, det);

        // 注: 本文中に元から U+FFFD が含まれる場合とデコード失敗の置換とを区別しない近似。
        //     文字コード取り違えの「示唆」用途であり、厳密な判定ではない。
        bool hadReplacement = text.Contains('�'); // U+FFFD REPLACEMENT CHARACTER
        LineEnding eol = LineEndingDetector.Detect(text);

        return new LoadedDocument
        {
            Text = text,
            Encoding = enc,
            HasBom = det.HasBom,
            LineEnding = eol,
            HadReplacementChar = hadReplacement,
        };
    }

    /// <summary>
    /// grep 用の復号(フェーズ 8・P-8)。<see cref="DecodeBytes"/> に codePage を強制したときの
    /// <see cref="LoadedDocument.Text"/> と同じ文字列を返す。grep が使わない改行コード判定
    /// (全文走査)と置換文字の走査を省く。BOM の判定も同じく <see cref="HasBomFor"/> で行う
    /// (EncodingDetector の HasBom は使わない=従来の grep と 1 バイトも違わない)。
    /// 等価性の網 = <c>TextFileServiceDecodeTextOnlyTests</c>。
    /// </summary>
    internal static string DecodeTextOnly(byte[] bytes, int codePage)
    {
        EncodingCatalog.EnsureRegistered();
        return DecodeBody(bytes, new DetectedEncoding(codePage, HasBomFor(bytes, codePage)));
    }

    /// <summary>
    /// BOM を除いた本文を、不正バイトを U+FFFD に落とすデコーダで復号する
    /// (<see cref="DecodeBytes"/> と <see cref="DecodeTextOnly"/> の共通部品)。
    /// </summary>
    private static string DecodeBody(byte[] bytes, DetectedEncoding det)
    {
        // 置換文字検出のため、不正バイトを U+FFFD（置換文字）に落とすデコーダを用意。
        // (元の DecodeBytes にあったコメント 4 行をそのまま移す)
        var decoder = Encoding.GetEncoding(
            det.CodePage,
            EncoderFallback.ReplacementFallback,
            new DecoderReplacementFallback("�")
        );

        // BOM を除いた本文部分をデコード。
        // (元の DecodeBytes にあったコメント 3 行をそのまま移す)
        int preambleLen = det.HasBom ? decoder.GetPreamble().Length : 0;
        return decoder.GetString(bytes, preambleLen, bytes.Length - preambleLen);
    }
```

### 以後への申し送り

- 先頭 8000 バイトより後ろにある NUL はテキスト扱いで照合され、`LineText` に NUL が含まれうる。これは本フェーズ以前からの既存の性質であり、本フェーズが作ったものではない(Task 2 の `Nul_beyond_sniff_window_is_scanned_as_text` で境界を固定済み)。表示側での無害化は将来の follow-up 候補。
- 正規表現モードでは、1 ファイル内のキャンセル不能時間に上限がない(行ごとに 1 秒のタイムアウトのため「行数 × 約 1 秒」になりうる)。`CollectLineHits` で N 行ごとに `CancellationToken` を確認すれば、プリフィルタのタイムアウトによる上乗せと合わせて改善できる。
- ヒット行の `LineText` は行全体を保持するので、64MB の 1 行で一致したファイルが多数あるとメモリを大きく使う(従来の Substring と同じ)。
