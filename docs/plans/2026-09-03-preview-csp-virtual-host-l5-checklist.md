## 実施の前提

- **NVDA を起動した状態で**実施する。SR 経路(`kxEdit.Accessibility` / UIA / Speech 系)には
  触れていないが、プレビュー窓の開閉とダイアログの文言は SR 利用者に直接届く。
- 実発声の逐語確認が要る項目(§F)は **NVDA スピーチビューアー**を開いて行う。
- 各項目は「合格条件」を満たすかで判定する。**落ちた場合は何が起きたかを書き残す**
  (特に §B は「塞げているか」ではなく「WebView2 が何をするか」を測る項目なので、
  結果がどちらでも情報価値がある)。

## 準備するフィクスチャ

```
C:\l5\secret.txt                 内容: L5-SECRET
C:\l5\prev\doc.md                以下の各項目で書き換える作業ファイル
C:\l5\prev\pic.png               任意の画像(表示されれば分かるもの)
C:\l5\prev\sub\child.png         同上(別の絵柄にすると弁別しやすい)

`doc.md` を kxEdit で開き、**表示 → マークダウンプレビュー**で確認する。

  [a](https://xn--あ/pic.png)
  <https://xn--あ/x>
  ![y](https://​.example/pic.png)

  ```
  (4 行目は U+200B、5 行目は U+FFFD を含む)
  **合格条件**: プレビュー窓が開き、**アプリが終了しない**。画像は表示されなくてよい。
  *落ちた場合*: 本ブランチの `1f81fd7` が効いていない。**マージしないこと。**

- [ ] **A-2. 深いネストでプレビューが落ちず、理由が伝わる**

  **合格条件**: **ダイアログが出てプレビュー窓は開かない**。アプリは終了しない。
  ダイアログの文言が「入れ子が深すぎる」旨で、原因が読み取れる。

## B. V-3 の前提と迂回形(WebView2 が実際に何をするか)

**この節は「防御が効いたか」ではなく「WebView2 の挙動を測る」のが目的。**
B-1 と B-2 の結果が V-3 の脅威度とガードの有効性そのものを決める。

- [ ] **B-1. WebView2 は `%2f` をパス区切りとして復号するか**
  `![a](https://kxedit.preview/sub%2fchild.png)`
  **表示された** = 復号する = V-3 は実在し、本ブランチのガードは load-bearing。
  **表示されない** = 復号しない = V-3 の脅威度は下がる(ガードは無駄ではないが優先度は落ちる)。
  → **結果をここに書く: ______**

- [ ] **B-2. `%252f` を二重復号しないか(本ガードの唯一の前提)**
  `![b](https://kxedit.preview/sub%252fchild.png)`
  **合格条件**: 表示されない。
  *表示された場合*: `%25` が二重復号されており、**無害化(`%2f`→`%252f`)は無効**。
  設計書 §14 の方式ごと作り直しになる。

- [ ] **B-3. 密輸された区切りでフォルダー外へ出られないか(相対形・絶対形)**
  ```markdown
  ![c1](..%2f..%2fsecret.txt)
  ![c2](https://kxedit.preview/..%2f..%2fsecret.txt)
  ```
  **合格条件**: どちらも `L5-SECRET` の内容が読まれない(画像なので表示されないのが正常。
  可能なら Fiddler 等で要求 URL を見る)。

- [ ] **B-4. 未保存タブ(空フォルダーへマッピング)でプロファイルへ届かないか**
  **無題タブ**(保存していない)に次を書いてプレビュー:
  ```markdown
  ![d](https://kxedit.preview/..%2f..%2fEBWebView/Default/Preferences)
  ```
  **合格条件**: 何も読まれない。
  *読まれた場合*: 空フォルダーは WebView2 プロファイルの直下 1 階層なので、
  **フォルダーマッピングをやめて `WebResourceRequested` で自前に返す方式へ切り替える**必要がある。

- [ ] **B-5. 生バックスラッシュが Windows のパス区切りとして復号されるか**
  `![f](https://kxedit.preview/sub\child.png)`
  **合格条件**: 表示されない(無害化されて `%255C` になっているため)。

- [ ] **B-6. 末尾ドットが仮想ホストマッピングに一致するか**
  `![g](https://kxedit.preview./pic.png)`
  **一致して表示される** = 末尾ドットは同じホストとして扱われる。
  **表示されない** = マッピングは一致しない(その場合、要求がネットワークへ出ていないかを確認)。
  → **結果をここに書く: ______**

- [ ] **B-7. percent-encoded ホストが正規化されてマッピングに一致するか**
  `![h](https://%6bxedit.preview/pic.png)`
  → **結果をここに書く: ______**(表示されたら Chromium のホスト正規化が効いている)

- [ ] **B-8. 非 ASCII ホストが正規化されてマッピングに一致するか**
  `![i](https://kxedit。preview/pic.png)`(`。` は U+3002)
  → **結果をここに書く: ______**

- [ ] **B-9. query はフォルダー解決に使われないか(未実測の前提の確認)**
  `![j](https://kxedit.preview/pic.png?x=%2f../secret.txt)`
  **合格条件**: `pic.png` が**表示される**(query は無視される)。

- [ ] **B-10. 別表記の区切りが復号されないか**
  ```markdown
  ![k1](https://kxedit.preview/sub%c0%afchild.png)
  ![k2](https://kxedit.preview/sub%ef%bc%8fchild.png)
  ```
  **合格条件**: どちらも表示されない。
  *表示された場合*: 無害化の対象表記を広げる必要がある。

## C. V-2 とマッピング

- [ ] **C-1. 未保存タブでプレビューが開き、実 DNS へ出ない**
  無題タブに `![](pic.png)` を書いてプレビュー。
  **合格条件**: 窓が開き、画像は「読み込めない」表示。**エラーダイアログは出ない**。
  `%LOCALAPPDATA%\kxEdit\WebView2\preview-*\empty-base` が作られている。

- [ ] **C-2. `empty-base` が空のまま・窓を閉じると消える**
  C-1 の状態で `empty-base` の中身を確認 → **空**であること。
  プレビュー窓を閉じたあと `preview-*` フォルダーごと消えていること。

- [ ] **C-3. 保存済み .md で相対画像が従来どおり表示される(回帰確認)**
  `doc.md` に `![p](pic.png)` と `![s](sub/child.png)` を書いてプレビュー。
  **合格条件**: 両方表示される。

- [ ] **C-4. 不達な共有上の .md で UI が固まらない**
  ネットワーク共有上の .md を開いた状態で共有を不達にする(または切断済みの共有を用意する)。
  そのタブでプレビュー。
  **合格条件**: **窓が即座に開き、UI が応答し続ける**(他のタブ操作・Esc が効く)。
  **最大 5 秒後に**画像なしの本文が表示される。
  **21 秒のフリーズが起きないことが合格条件で、「即座に本文が出る」ことではない。**
  ※ ネットワーク設定の変更を伴うので、実施可否はユーザーの判断で。
