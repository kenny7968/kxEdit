# L5(実機 SR 検証)チェックリスト — 設定ダイアログの寸法決定 (Issue #68)

対象ブランチ: `feature/settings-dialog-size`
設計書: `2026-09-04-settings-dialog-size-design.md` / 実装計画: 同名(`-design` なし)

**このブランチの L5 は必須**(設計書 §5)。理由は 2 つ:

1. Dock の追加順を変えたため `Controls` の z-order が変わる。本ダイアログは `TabIndex` を
   明示していないので、**Tab キーの巡回順と UIA ツリーの子順序が変わりうる**
   (従来「ボタン列 → TabControl」→ 変更後「TabControl → ボタン列」)。
2. ダイアログを開いたまま内容が伸びたときに**寸法がその場で広がる**挙動を新設した。
   広がった瞬間にフォーカスや読み上げが乱れないかは実機でしか見られない。

**判定欄は実施前なので空にしてある。** 実施時に **PASS / FAIL / N/A** を記入し、FAIL は
**聞こえた文言を逐語で**残す(要約しない)。

> ## 📌 このチェックリストは「マウスで見る」項目を含む
>
> Issue #68 は **SR 経路が生きたまま視覚的にだけ壊れていた**不具合である
> (キーボード / UIA では正常に見えるため SR 中心の検証で見逃されていた)。
> CLAUDE.md §2「晴眼・弱視ユーザーも第一級」に照らし、**§1 は必ず目視とマウスで**確認すること。
> NVDA を落として確認しても構わない(§1 に読み上げの検証は無い)。

## 4. 実行時に寸法が広がる挙動(今回の新設)

**背景**: [表示]タブのフォント名ラベルは、フォントを選び直すとその場で伸びる。開いた時点の寸法で
固定するとラベルが切れるため、ページ本体の `Layout` を購読して**広げる方向にのみ**追随する。

| # | 手順 | 期待 | 判定 |
|---|------|------|------|
| 4.1 | 設定 → [表示]タブ → 「変更(&F)...」でフォント名の**長いフォント**を選ぶ | ダイアログが必要なぶん広がり、フォント名ラベルと最下段のチェックボックスが**切れない**(目視) | |
| 4.2 | 4.1 の直後に聞く | 寸法が変わってもフォーカスは失われず、読み上げが乱れない(無音になる・別項目へ飛ぶ・同じ内容を繰り返す等が起きない) | |
| 4.3 | 4.1 の後、`Tab` で巡回する | §2 と同じ順序を保っている | |
| 4.4 | 4.1 の後、**短い名前のフォント**に戻す | ダイアログは**縮まない**(仕様どおり。操作中に座標が跳ばないため)。見た目に破綻がない | |
| 4.5 | OK で閉じてもう一度開く | 今度は最初から適切な寸法で開く(長いフォント名を反映した幅) | |

## 5. 設定値による寸法(仕様レビューが掘り当てた欠陥の実機確認)

既定の `ＭＳ ゴシック` でたまたま余白 0 で収まっていただけで、より長い名前の設定では毎回溢れていた。

| 5.2 | 5.1 で [表示]タブの最下段まで `Tab` で移動する | 最後の項目までフォーカスが届き、読まれる | |
