# kxEdit v0.2 リリース前バグ監査(2026-08-22)

main = `119ae33`(PR #40 マージ後)に対する、リリース前の致命バグ調査の記録。
本書は**策定時スナップショット**(CLAUDE.md §8)。修正は本書に書き戻さず、各修正の設計書 / PR で管理する。

## 1. 目的と方法

- 目的: v0.2.0(改名後初リリース)として出荷してよいか、critical / important な欠陥の有無を判定し、修正優先順位の材料を作る。minor・レアケースは将来対応記録として残す。
- ベースライン: `tools/pre-merge-check.ps1` EXIT 0(Core 1139 / Editor 366 / App 474 全緑・0 warning)。
- 方法: ソースを 7 領域に分けて独立エージェントがコード読解で監査(Core バッファ / Core IO・バックアップ・セッション / Core 検索・レイアウト・CSV・Markdown / Editor / UIA・Speech / App ライフサイクル / App 機能)+ 既知申し送りの棚卸し 1 本。出てきた指摘はコーディネータが再読・実機(Windows-MCP)・実ビルド DLL で検証し、反証できたものは落とした。
- 検証状態の凡例: **[実機]** = 実際のアプリで再現、**[DLL]** = ビルド済み DLL を外部から呼んで再現、**[コード]** = 呼び出し経路まで読んで確定、**[推定]** = 機構は確定だが発現条件が環境依存。

### 判定基準

| 区分 | 定義 |
|------|------|
| Critical | ユーザーデータの喪失・破壊、または通常操作でのクラッシュ/ハング |
| Important | 通常使用で気づく誤動作、説明書が謳う機能の不全、現実的な経路でのクラッシュ |
| Minor | レアな前提が必要、影響が軽微、理論上の問題 |

## 2. 総評

- **Critical(通常操作で無条件に起きるデータ喪失・クラッシュ)は見つからなかった。** 原子保存・保存失敗時ロールバック・終了経路の保存確認・破損設定/セッションファイルからの起動・UIA のスレッド分離は、いずれも意図どおり機能していることを確認した。
- ただし **Important が多数**あり、そのうち 3 件は実機/DLL で再現済み。特に「保存直後のクラッシュで古いバックアップが保存済みファイルを上書きする導線」「マークダウンプレビューの CSS・ローカル画像が一切効いていない(v0.1.1 からの退行)」「検索・行移動・grep ジャンプで画面がスクロールしない」は、晴眼ユーザーが初日に気づく水準。
- プロセス面では、SR 経路に触れた PR #36〜#39 の **L5(実機 SR 検証)が未実施のまま main に積まれている**ことが最大のリスク(§5)。

## 3. 優先度 1 — リリース前に修正を推奨

### A-1. 保存後〜次 tick の間にクラッシュすると、古いバックアップが dirty として復元され Ctrl+S で新しい内容を旧内容で上書きする [コード]

- 場所: `src/kxEdit.App/BackupCoordinator.cs:123-124`(Reconcile の契機は Timer と ActiveDocumentChanged のみ)、`src/kxEdit.App/FileController.cs:433`(SetSavePoint は Coordinator に通知しない)、`:694-701`(レイアウト記録+バックアップがあれば無条件に `RestoreDirtyFromBackup`)。
- 再現: バックアップ ON で編集 → tick でバックアップ B 書込 → さらに編集して Ctrl+S(成功)→ 次 tick(既定 300 秒)までにクラッシュ/電源断 → 再起動で `* file.txt` として**保存前の本文**が復元 → ユーザーが Ctrl+S → 保存済みの新内容が無警告で消える。OFF 経路(起動時確認ダイアログ)でも同じ古い B が提案される。
- 復元側はディスクの LastWriteTime とバックアップの TimestampUtc を比較していない。
- 修正の当たり: (a) `SavePointReached`(保存成功)で即 Reconcile(バックアップ削除+レイアウト更新)、(b) 復元時に `File.GetLastWriteTimeUtc(path) > bk.TimestampUtc` なら警告またはディスク版を優先。(a)(b) 両方が望ましい。
- 既存テスト: `BackupCoordinatorTests.Reconcile_DirtyThenSaved_DeletesBackup` は「次 Reconcile で消える」ことのみ固定。

### A-2. マークダウンプレビューで CSS・相対パス画像・相対リンクが解決されない(v0.1.1 MD-M-2 からの退行) [実機]

- 場所: `src/kxEdit.Core/Text/MarkdownRenderer.cs:46`(`base-uri 'none'`)、`:124-126`(`<base href="https://kxedit.preview/">`)、`:141`(`<link href="/_kxedit/styles.css">`)。
- 機構: `<meta http-equiv=CSP>` が `<base>` より前にあり、`base-uri 'none'` は仕様上 `<base href>` を無効化する。文書は `NavigateToString`(data: 起点)なので、ルート相対 `/_kxedit/styles.css` も相対 `pic.png` も解決できない。
- 実機確認(2026-08-22): `![local image](pic.png)` は壊れた画像+alt テキスト表示、blockquote の左ボーダー・本文パディングなど CSS も未適用。説明書 §7 / §12.1「ローカルにある画像は表示されます」と矛盾。
- 修正の当たり: `base-uri 'none'` → `base-uri https://kxedit.preview/`(許可ホストに限定すれば MD-M-2 の意図は保てる)。`MarkdownRendererTests.Meta_Contains_BaseUri_None` の更新が必要。修正後は L5 チェックリスト ④(`2026-08-21-rename-to-kxedit-l5-checklist.md`)で実機確認。
- 補足: `PreviewCspHeaderInjectorTests` は WebView2 実機を使わないため、この種の「CSP 同士の食い合い」は自動テストでは検出できない。

### A-3. 検索ジャンプ・Ctrl+G・grep ジャンプで画面がスクロールしない(晴眼ユーザー向け退行) [実機]

- 場所: `src/kxEdit.Editor/EditorControl.Caret.cs:104-120`(`SetCaretCharOffset`)、`:143-161`(`SetSelectionCharRange`)— `PositionCaret()`+`Invalidate()` のみで `BringCaretIntoView` を呼ばない。App 側で `EnsureVisibleCharRange` を呼ぶのは `CsvController.cs:254, 363` だけ(`SearchController.cs:232, 308` / `MainForm.cs:847, 883` / `KinsokuFormatController.cs:151-153` は未呼出)。
- 実機確認: 308 行の説明書を開き Ctrl+G → 250 → ステータスバーは「行 250, 桁 1」だがビューポートは 1 行目のまま。
- 旧 `ScintillaHost.SelectCharRange` は `SCI_SCROLLCARET` を発行していた(P6 の自作エディタ移行で落ちた契約)。NVDA 稼働中は UIA `ScrollIntoView`(PR #29)経由で追従しうるため L5 では露見しにくい。
- 修正の当たり: Editor 側 `SetCaretCharOffset` / `SetSelectionCharRange` で `BringCaretIntoView()` を呼ぶ(UIA `Select()` 経路も同時に直る=§4 A-12 の姉妹)。`EditorControlCompatApiTests.GoToLine_*` に `TopLine` の assertion を追加。

### A-4. ネットワーク共有(UNC / マップドドライブ)へ新規ファイルを「名前を付けて保存」できない [コード]

- 場所: `src/kxEdit.App/FileReachabilityProbe.cs:20`(`File.Exists(path)`)、`src/kxEdit.App/FileController.cs:403`(`WriteToPath` 冒頭の `TryProbeReachability`)。
- 機構: 到達性プローブが「ファイルの存在」を返すため、存在しない新規パスは到達可能でも常に false → 「ネットワークパスに到達できません」。既存ファイルの上書きだけ通る。CSV-M-2(2026-07-20)で Save 側に足したときの退行。
- 既存テスト: `FakeReachabilityProbe` で固定値を返すため実 Probe の意味論は未検証。
- 修正の当たり: Save 側は `File.Exists(path) || Directory.Exists(Path.GetDirectoryName(path))` を判定に使う。

### A-5. 折り返し ON で ↑ が効かなくなる / ↓ が視覚行を 1 行飛ばす [DLL]

- 場所: `src/kxEdit.Core/Editing/VerticalNavigation.cs:139-142`(`PxToOffset` の戻り値をそのまま採用)、`src/kxEdit.Core/Layout/PixelMapper.cs:44-45`(`px >= total → segment.Length`)、`src/kxEdit.Core/Layout/VisualSegments.cs:30`(`offset < segEnd` で次セグメント扱い)。
- 機構: desiredPx が移動先(非最終)セグメントの幅以上のとき、着地オフセットが「そのセグメント末尾=次セグメント先頭」になる。次の ↑ は `FindContaining` が次セグメントと判定し、1 つ戻した先で再び同じオフセットに着地=動かない。
- 再現(MonoCharMetrics 8px・wrapColumns=4・`"abcd\nxxxxyyyyzzzz\nend"`): 行 0 行末(caret=4)で ↓ → caret=9(`xxxx` 行を飛ばして `yyyy` 行頭)。続けて ↑ ×3 → caret=9 のまま。
- 発生条件: 全角段落は各視覚行が幅いっぱいになるため「段落末尾 → ↑」「幅いっぱいの行の行末 → ↓」で日常的に踏む。**既知 E-1(折り返し ON の ↓ で NVDA が「ブランク」)と同根の可能性**があるので、修正時に E-1 を再検証する。
- 既存テスト: `VerticalNavigationTests` の wrap 系はセグメント中央の桁のみ(右端ケース未被覆)。
- 修正の当たり: 非最終セグメントでは着地を `segment.Length - 1` 以下にクランプする(または `FindContaining` と同じ境界規約を `PxToOffset` 側に持たせる)。

### A-6. 折り返し ON でキャレットが可視域外に出ても追従スクロールしない [コード]

- 場所: `src/kxEdit.Editor/EditorControl.Caret.cs:296-314`(`BringCaretIntoView` は論理行で判定)、`:271`(`VisibleRowCount`)。コメント自身が「近似」と明記。
- 再現: 折り返し ON・各段落が 5 視覚行以上・30 行ウィンドウで先頭から ↓ 連打 → 論理行 6 あたりで `ComputeCaretPoint` が `Visible=false` → システムキャレットは (-1000,-1000) へ退避、論理行 30 に達するまでスクロールしない。ビューポートより背の高い段落(巨大 1 行)ではその下が永久に見えない。
- 折り返しはオプトインだが、晴眼・弱視ユーザーの通常編集で確実に遭遇する。`TopLine` が論理行単位である限り根治には視覚行スクロールが要る=設計判断が必要(A-5 と合わせて「折り返し ON の垂直移動」として 1 テーマに束ねるのが妥当)。

### A-7. 「名前を付けて保存」の手入力パスに上書き確認がなく、他タブで開いているファイルとの重複も検知しない [コード]

- 場所: `src/kxEdit.App/SaveAsDialog.cs`(テキストボックス直入力はそのまま返す。`参照` ボタンの `SaveFileDialog` だけ OverwritePrompt が効く)、`src/kxEdit.App/FileController.cs:294-352`(空白チェックのみ → `WriteToPath`)、`src/kxEdit.Core/IO/AtomicFile.cs:82-86`(存在すれば `File.Replace`)。
- 再現 (a): SR ユーザーの主経路であるテキストボックスに既存ファイル名を打って OK → 無確認で置換。
- 再現 (b): タブ A=`foo.txt` を開いたまま、無題タブ B を `foo.txt` に保存 → A は古い内容を表示したまま → A で 1 文字編集して Ctrl+S → B の内容が消える。hot exit レイアウトにも同一 Path が 2 件並ぶ。
- メモリ「M2 申し送り: SaveAs 重複ガード」が未回収のまま。
- 修正の当たり: `File.Exists` なら上書き確認、`FindByPath` 一致なら警告(または既存タブへ統合)。

### A-8. hot exit の確認なしクローズが、バックアップ書込失敗を確認せずに終了する [コード]

- 場所: `src/kxEdit.App/MainForm.cs:381-384, 425-426, 459`、`src/kxEdit.App/BackupCoordinator.cs:621-631`(FinalFlushForRestore)、`:407-410`(`_failed` の回収は次 Reconcile 冒頭のみ)、`src/kxEdit.App/SerialBackupWriter.cs:43-54`。

- 修正の当たり: FinalFlush 後に writer の完了と失敗を待ち合わせ、失敗があれば従来の「保存しますか」確認へフォールバック。

## 7. 問題なしと確認した領域(再監査時の省力化のため)

- PieceTree(AVL join / Split の Breaks 補正)・TextChunk 格子と CRLF 規約・AppendBuffer 共有ブロック・`TextBuffer.Splice`(サロゲート前方スナップ・上限判定の順序)・Undo 保存点・`TextSnapshot` の行末/行数・`TextBufferBuilder` の繰越し。
- `AtomicFile`(tmp 同ディレクトリ・失敗時原本不変)・`TextFileService.Save` の BOM 制御・SJIS/EUC-JP の `Encoder.Convert` 状態持ち越し・`LoadAsBufferAuto` の大容量経路・`BackupStore` の Id 白リスト・`SessionLayoutStore` / `SettingsStore.Load` の破損耐性(起動クラッシュ経路なし)。
- `LiteralWindowSearchStrategy.FindNext` / `Count` の窓境界・`TextSearcher` の 1 秒タイムアウトとゼロ幅前進・`RegexPerLineSearchStrategy.ReplaceInRange`・`GrepService` の行番号/オフセット・`LineLayout.WrapCore`(幅超過 1 文字・サロゲート非分割)・`ViewportLayout` の最終行・`CsvParser` / `CsvWriter.EscapeField`・`KinsokuFormatter` の停止性・`SafeLinkExtension` の scheme 回避(大文字・空白・制御文字・HTML エンティティ・autolink)・`MarkdownRenderer` の 4M 上限。
- P/Invoke 署名(x64)・GDI/IMM ハンドル寿命・IME 二重確定/消失・CRLF/サロゲートの原子性・Undo/Redo のキャレット・選択セマンティクス・マウス・スクロールバー算術・`OnPaint` の例外面。
- UIA: `_bufferSnapshot` の volatile と不変スナップショット・全 host メソッドのクランプ・単位歩進(Char/Word/Line)・cap(128)・`FindText` のチャンク境界・イベント順序・Announcer の UI スレッド性。
- 終了経路の網羅性(X / Alt+F4 / 終了 / 最後のタブ / シャットダウン)と 3 値分岐・`_discarded` の確定タイミング・復元タブの Modified=true・Save 失敗時ロールバック・`TryOpenOrActivate` の重複防止・`PreviewNavigationPolicy.Classify`・`PreviewUserDataFolder`・WebView2 ランタイム欠如の扱い・GoToLine / GoToCell の入力検証・`CsvCellEditor` の確定/取消・`GrepController` のキャンセル/追い越し。
