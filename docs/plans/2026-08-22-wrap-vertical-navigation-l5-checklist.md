## なぜ L5 が必須か

本ブランチは UIA の可視域報告(`GetVisibleRanges` / `ScrollIntoView` / `GetBoundingRectangles`)の
起点を論理行から**視覚行**へ移している = CLAUDE.md §5 の「SR 経路に触れる変更」に該当する。
加えて **⑦ は自動テストでは原理的に確認できない**(オフスクリーン Form には WM_PAINT が
配送されないため、`BuildVisibleRows` への集約で守れるのは「起点が食い違わないこと」までで、
実際に段落の途中から描かれること自体は実機でしか見えない)。

## 実施前の準備

1. Release ビルドの kxEdit を起動する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動しておく(**②・⑦ は NVDA 動作中でないと再現条件を満たさない**。
   PR #34 の教訓 = 否定命題は条件同一性がすべて)。
3. 検証用ファイルを 3 つ用意する。
   - **通常文書**: 普通の日本語テキスト(段落が数十行)。
   - **巨大 1 行**: 改行を 1 つも含まない CJK 500K 文字。
     `dotnet run --project tests/kxEdit.Editor.Smoke -c Release -- --wrapscroll` が使うのと同じ性質の
     ファイル。手元に無ければメモ帳等で「あいうえお…」を貼り付けて量産してもよい。
   - **折り返し OFF 確認用**: ①③ と同じ 2 ファイルを使い回してよい。
4. [表示]メニュー(または設定)で**折り返しを ON** にできることを確認する。

## ① A-5 主経路 — 折り返し ON で ↓↑ が 1 視覚行ずつ動く

**手順**

1. **通常文書**を開き、折り返しを **ON** にする。

**期待**

## ⑦ 段落の途中までスクロールした状態が正しく描画される(**L5 でしか見られない**)

自動テストは `BuildVisibleRows` への集約で「描画・座標・ヒットテスト・可視域報告の
起点が食い違わないこと」までしか守れない。**オフスクリーン Form には WM_PAINT が
配送されない**ため、実際に段落の途中から描かれること自体は実機でしか確認できない
(PR #34 の教訓 = `GdiBench` の L4 ゲートが描画せず PASS していた疑い)。

**手順**

1. **巨大 1 行**(または長い段落を含む通常文書)を折り返し ON で開く。
2. ホイールで**段落の途中まで**スクロールする(先頭が段落の途中の視覚行になる状態)。
3. 画面最上段に表示されている文字列を**目で確認**する。
4. その最上段の行頭を**クリック**し、NVDA が読む文字と画面の文字が一致するか確認する。
5. その位置から ↓↑ を数回押す。

**期待**

- 画面最上段が**段落の途中の視覚行**から描かれている(先頭に戻っていない・空白になっていない)。
- 画面の内容と NVDA の読みが**一致する**(描画の起点と可視域報告の起点が同じ)。
- クリック位置にキャレットが立つ(ヒットテストの起点も同じ)。
- 行が重複表示されたり、1 本ずれたりしない。

**結果**: ☐ PASS ☐ FAIL — 備考:

## ⑧ 垂直スクロールバーのサムが段落内で動かないこと(**仕様・バグではない**)

設計書 §4.4 の**意識的な近似**。スクロールバーは論理行基準のまま(`Value = TopLine`)なので、
段落の途中をスクロールしている間サムは動かず、**論理行 1 本の文書ではバーが無効のまま**になる。
全文の視覚行数を数えると O(文書) になり PR #35 の退行になるため、あえて据え置いた
(申し送り S-3)。**これを「バグ」と誤認しないための確認項目**である。

**手順**

1. **巨大 1 行**を折り返し ON で開く。
2. ホイールを下へ数十ノッチ回す。
3. 垂直スクロールバーを見る。
4. **通常文書**でも、長い段落の途中でホイールを 1〜2 ノッチ回してサムを見る。

**期待**(=**仕様どおり**)

- 巨大 1 行では**サムが動かない / バーが無効**のまま。それでも**本文はスクロールする**。
- 通常文書では、段落を跨ぐときだけサムが動き、段落の**途中**では動かない。
- **本文が動いていれば PASS**。サムが動かないこと自体は FAIL ではない。

**結果**: ☐ 仕様どおり ☐ 想定外(本文もスクロールしない等)— 備考:

## 判定

- **① / ③ が FAIL は即マージ中止**。A-5 / A-6 の主症状そのものが直っていない。
- **⑥ が FAIL は即マージ中止**。折り返し OFF の退行は本ブランチで最も重い事故
  (不変条件 I-3 が破れている = 自動テストの網が届いていない箇所がある)。
- **⑦ が FAIL** → 描画側(`ViewportLayout.Build` の topSegment 読み飛ばし)と
  報告側(`ComputeCaretPoint` の `segIdx < _topSegment`)の起点がずれている。
  該当コミットは Task 4「座標・ヒットテスト・可視域報告を TopSegment 起点にする」。
- **② が FAIL** → 本ブランチのマージは可。E-1 を UIA 側の独立欠陥として起票する(S-5)。
- **④ / ⑤ が FAIL** → 該当経路(`EnsureVisibleCharRange` / `InputRouter` の Page 系)を
  個別に切り分ける。①③⑥ が PASS なら基盤は成立している。
- **⑧ が「想定外」** → 本文がスクロールしないなら ③ の再確認へ戻る。

総合: ☐ マージ可 ☐ 要修正
