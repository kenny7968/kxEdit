## なぜ L5 が必須か

SR 経路(`EditorControl` の UIA 部)に**触れている**。CLAUDE.md §5 の
「SR 経路に触れる変更は必須」に直接該当する。

1. **UIA イベントの発火時点が変わった。** 修正前の `ConvertEols` は `ReplaceSource` 経由で
   キャレットを一度 0 に潰し、その**中間状態で** `TextChanged` / `SelectionChanged` を発火して
   いた(監査 A-11 が副作用として指摘)。修正後はキャレット復元後に 1 回だけ発火する。
   **回数は修正前後とも 1 回**なので自動テストでは「発火時点の caret 値」しか固定できず
   (L2 で `caret=0` → `caret=8` の差は pin 済み)、**SR が実際にどう読むかは実機でしか判らない**。
2. **保存後の Ctrl+Z が初めて機能する。** A-11 の修正そのもの。押しても何も起きなかった操作が
   本文を巻き戻すようになるので、**その巻き戻しが読まれるか**は実機確認が要る。
3. **キャレットが文書末尾へ飛ぶ受容済み挙動がある**(§10.11 (5))。全文差し替えを 1 Undo 単位に
   する以上、Undo の推奨キャレット位置は `Pos + RemovedLen` = 文書末尾になる。
   **ユーザーが現在位置を見失わないか**が実機判定の対象。
4. **晴眼・弱視ユーザー向けの挙動改善が 2 件ある**(CLAUDE.md §2「晴眼・弱視ユーザーも第一級」)。
   水平スクロール位置の保持と、保存失敗時のキャレット/選択/表示位置の復元。
   どちらも「画面が飛ばないこと」の確認なので目視が要る。

**各項目に「自動テストが届かない範囲」を明記した。** 該当が無い項目は
「L2 / L3 で pin 済み・実機は聞こえ方と見え方の確認」と書いてある。

> **注意**: PR #36〜#39 / #42 / #43 / #45 / #46 / #47 / #50 の L5 と、PR #51 の手動スモークが
> 未実施のまま積まれている(PR #27 / #29 / #35 / #53 は L5 実施済)。
> 本チェックリストと**同じセッションでまとめて実施**するのが望ましい。

## 実施前の準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動しておく(発声の確認が目的なので、スピーチビューアーだけに頼らない)。
   ただし**スピーチビューアーも併用**すると発話の逐語確認ができる。
3. 作業用フォルダーを 1 つ作り、次のファイルを置く。**いずれも kxEdit 以外で作ること**
   (メモ帳・PowerShell 等。kxEdit で作ると保存時に EOL が統一されてしまう)。

   | ファイル | 内容 | 用途 |
   |---|---|---|
   | `lf-long-first-line.txt` | 1 行目が **5,000 文字以上**の ASCII 文字列、その後に `\n` 区切りで数行。**改行はすべて LF** | ① |
   | `mixed-eol.txt` | CRLF が多数派、LF が数個混ざる。行数は **5,000 行以上** | ②③④ |
   | `wide-line.txt` | 200 文字超の長い行を **50 行目付近**に 1 本だけ持ち、全体は 300 行以上。改行は LF | ⑤ |
   | `readonly.txt` | 任意の内容(改行は LF)。**読み取り専用属性を立てる** | ⑥ |

   PowerShell での作成例(`>` の既定エンコードに注意。UTF-8 を明示すること):

   ```powershell
   # LF 改行で書くため -NoNewline + "`n" を使う
   $long = 'a' * 5000
   [IO.File]::WriteAllText("$PWD\lf-long-first-line.txt", "$long`nsecond`nthird`n", [Text.UTF8Encoding]::new($false))
   ```

4. [ツール]>[設定] で**改行コードの既定**を確認できるようにしておく(②③ で切り替える)。
5. `readonly.txt` は `attrib +R readonly.txt` で読み取り専用にする。

## ① A-9 — 1 行目が長い LF ファイルが LF のまま保存される

**これが A-9 の中核。** 修正前は改行判定が先頭 4,096 文字だけを見ていたため、1 行目が
それより長い LF ファイルは**改行が 1 つも見つからず CRLF 既定**へ倒れ、Ctrl+S で
**全行が無警告に CRLF 化**されていた(Modified も立たないので気づけない)。

**自動テストが届かない範囲**: ステータスバーの EOL 表示を **NVDA がどう読むか**。
判定ロジック自体は L1 で pin 済み(`LoadAuto_LfFile_FirstLineLongerThanOldProbeWindow_DetectsLf`)。

**操作手順**

1. `lf-long-first-line.txt` を開く。
2. ステータスバーの改行コード表示を確認する(目視 + NVDA で読ませる)。
3. 本文の末尾に 1 文字入力して Ctrl+S。
4. kxEdit を閉じ、**kxEdit 以外**(PowerShell 等)でファイルの改行コードを確認する。

   ```powershell
   $b = [IO.File]::ReadAllBytes("$PWD\lf-long-first-line.txt")
   "CR={0} LF={1}" -f ($b | ? {$_ -eq 13}).Count, ($b | ? {$_ -eq 10}).Count
   ```

**期待**

- 手順 2 で **`LF`** と表示・発声される(修正前は `CRLF`)。
- 手順 4 で **CR の数が 0**(修正前は LF と同数の CR が入っていた)。

## ② A-11 — 保存直後の Ctrl+Z が本文を巻き戻す

**これが A-11 の中核。** 修正前は `ConvertEols` が新しいバッファへ差し替えていたため
Undo 履歴が全消去され、**Ctrl+Z が無反応**だった。

**自動テストが届かない範囲**: 巻き戻しを NVDA が読むか。本文が戻ること自体は L2 / L3 で pin 済み。

**操作手順**

1. [ツール]>[設定] で改行コードの既定を **LF** にする。
2. `mixed-eol.txt`(CRLF 多数派)を開く。ステータスバーが `CRLF` であることを確認。
3. 任意の位置に 1 文字入力する(Modified にする)。
4. **Ctrl+S**。
5. **Ctrl+Z**。

**期待**

- 手順 5 で本文が変換前(CRLF 混在)へ戻る。
- タブラベルに `*`(未保存マーク)が付く。**NVDA がタブの状態変化を読むか**を確認。
- 「やり直し」(Ctrl+Y)は**無効**である(§10.14 (3) の決定: ロールバックは Redo を残さない)。

## ③ 受容済み挙動 — Ctrl+Z 後のキャレット位置(§10.11 (5) / §10.12 (3) の回収)

**これは「直す/直さない」の判断材料を取る項目**であり、期待どおりでも FAIL ではない。

全文差し替えを 1 Undo 単位にする以上、Undo の推奨キャレット位置は `Pos + RemovedLen`
= **文書末尾**になる(`Replace(0, len, text)` でも同じで、異常な挙動ではない)。
`EditorControl` に EOL 変換専用の特例を作ると汎用 Undo 経路に分岐が入って他の意味論を
壊すリスクがあるため、**受容**した。

**自動テストが届かない範囲**: ユーザーが現在位置を見失うかどうか。原理的に実機判定のみ。

**操作手順**

1. ② と同じ条件(設定 LF / `mixed-eol.txt`)。
2. **5,000 行目付近**にキャレットを置く(Ctrl+G で行ジャンプ)。
3. 1 文字入力して **Ctrl+S**。
4. **Ctrl+Z**。

**期待**(受容済み挙動)

- 本文が変換前へ戻る。
- キャレットと表示が**文書末尾**へ移動する。

**判定**

- NVDA がその移動を読み上げるか。☐ 読む ☐ 読まない
- ユーザーが現在位置を見失うか。☐ 見失わない ☐ **見失う**

**見失う場合**: 設計書 §10.11 (5) の (b) 案(`ConvertEols` が保持している `(m, k)` 分解から
復元位置へ戻す)を申し送りとして回収する。**マージは止めない**(受容済み挙動のため)。

☐ 実施済み — 備考:

## ④ 挙動変更 — UIA イベントが caret 復元後に 1 回だけ飛ぶ

修正前は `ReplaceSource` がキャレットを 0 に潰し、**その中間状態で** `TextChanged` /
`SelectionChanged` を発火していた。SR クライアントは「保存したらキャレットが先頭へ飛んだ」という
**誤情報**を受け取り、その後キャレットが復元されても**通知が来ない**状態だった。

**自動テストが届かない範囲**: **実発声そのもの**。発火時点の caret 値は L2 で pin 済み
(`ConvertEols_NonFastPath_RaisesUiaEventsAfterCaretRestore` が `caret=0` → `caret=8` を固定)。
**回数は修正前後とも 1 回**なので、回数では区別できない。

**操作手順**

1. ② と同じ条件。文書の**中ほど**(例: 100 行目)にキャレットを置く。
2. 1 文字入力して **Ctrl+S**。
3. 保存直後に、NVDA で現在行を読ませる(NVDA+↑ 等)。

**期待**

- 保存の前後でキャレット位置が変わらない。
- 手順 3 で読まれる行が**保存前と同じ行**である。
- 保存時に「1 行目」「先頭」に相当する発話が**挟まらない**(修正前はここで caret=0 の通知が
  飛んでいたため、SR によっては先頭へ飛んだように読まれていた可能性がある)。

☐ PASS ☐ FAIL — 備考(修正前後で発話が変わったか。スピーチビューアーの逐語記録があれば添付):

## ⑤ 挙動改善 — Ctrl+S で水平スクロール位置が消えない(晴眼・弱視)

**main 既存バグの解消でもある**(§10.13 (7))。修正前は保存のたびに水平スクロール位置が
0 へ戻っていた。`UpdateHorizontalScrollbar` が「**可視行**のうち最長 pixel 幅」で extent を
決めるため、長い行が可視域の外にあると水平スクロールバーごと消えて `_scrollX` が 0 に落ちる。

**自動テストが届かない範囲**: なし(L2 の
`ConvertEols_NonFastPath_KeepsHorizontalScroll_WhenLongLineOffFirstScreen` で pin 済み)。
**実機では「画面が横に飛ばないこと」の目視確認**として行う。

**操作手順**

1. 設定の改行コードを **CRLF** にする(`wide-line.txt` は LF なので非 fast-path になる)。
2. `wide-line.txt` を開き、折り返しを **OFF** にする。
3. 50 行目付近の長い行へ移動し、**右へ水平スクロール**する(End キーまたは水平スクロールバー)。
4. その状態から**長い行が画面外になるまで下へスクロール**する(例: 200 行目付近を表示)。
5. 1 文字入力して **Ctrl+S**。

**期待**

- 保存後も**水平スクロール位置が保たれる**(画面が左端へ飛ばない)。
- 垂直スクロール位置も保たれる。

☐ PASS ☐ FAIL — 備考:

## ⑥ 保存失敗時のロールバック — キャレット・選択・表示位置が直前と同じ(§10.14 (8) の回収)

修正前(main)は保存失敗のロールバックで `ReplaceSource` を通していたため、
**キャレットもスクロールも 0 へ潰していた**。修正後は保存前の位置へ明示復元する。

**自動テストが届かない範囲**: ダイアログを閉じた後のフォーカス遷移と、NVDA が
「キャレットが飛んだ」と読む発話が挟まらないか。復元自体は L3 で pin 済み
(`Save_WriteFailure_OnNonFastPathEol_RestoresCaretAndScroll`)。

**操作手順**

1. 設定の改行コードを **CRLF** にする(`readonly.txt` は LF なので非 fast-path になる)。
2. `readonly.txt` を開く。
3. 文書の**途中**にキャレットを置き、**数文字を選択**する。
4. 1 文字入力して(選択が置換される)、さらに数文字を選択し直す。
5. **Ctrl+S**。「保存できませんでした」ダイアログが出る。
6. ダイアログを閉じる。

**期待**

- 本文が**変換前のまま**(CRLF 化されていない)。
- **キャレット位置・選択範囲・表示位置が Ctrl+S の直前と同じ**。
- タブラベルの `*` が残っている(未保存のまま)。
- NVDA が「キャレットが飛んだ」に相当する発話を**しない**。

## ⑦ CSV グリッドモードでのロールバック(`ReadOnly` 経路)

`EditorControl.Undo()` は `ReadOnly` で早期 return するため、ロールバックに流用すると
**CSV グリッドモードで黙って no-op** になる。専用 API(`UndoEolConversion`)がこれを回避している。

**自動テストが届かない範囲**: なし(L2 / L3 で pin 済み)。**実機では経路が実在することの確認**。

**操作手順**

1. 読み取り専用属性の CSV ファイルを 1 つ用意する(`readonly.csv`・改行は LF)。
2. 設定の改行コードを **CRLF** にする。
3. kxEdit で開き、**CSV モード**に入る。
4. セルを 1 つ編集して確定する。
5. **Ctrl+S**。

**期待**

- 「保存できませんでした」ダイアログが出る。
- 本文が**変換前のまま**(CRLF 化されていない)。
- グリッドの選択セルが保存前と同じ。

☐ PASS ☐ FAIL ☐ スキップ(CSV モードで読み取り専用が開けない場合) — 備考:

## 判定

- **① が FAIL → 即マージ中止。** A-9 が直っていない。サイレントな全行書換が残る。
- **② が FAIL → 即マージ中止。** A-11 が直っていない。
- **⑤ / ⑥ が FAIL → 即マージ中止。** どちらも本ブランチが「直した」と主張している挙動改善で、
  自動テストで pin 済みのものが実機で再現しないなら網か実装のどちらかが誤っている。
- **④ が FAIL(保存時に先頭へ飛んだように読まれる)→ 要調査。** 修正の主目的の 1 つが
  達成できていない。ただし SR の読み上げ規則によっては修正前後で差が出ない可能性もあるため、
  スピーチビューアーの逐語記録を添えて判断する。
- **③ は FAIL 判定なし**(受容済み挙動の材料取り)。「見失う」なら §10.11 (5) (b) 案を
  申し送りへ回収する。**マージは止めない。**
- **⑦ が FAIL → 要調査。** `UndoEolConversion` の `ReadOnly` 非依存が効いていない。
  スキップした場合は L2 / L3 の網に依拠する。
- **⑧ が FAIL → 即マージ中止。** 既存経路の退行。

総合: ☐ マージ可 ☐ 要修正
