# L5(実機 SR 検証)チェックリスト — WinForms の IME モード推測を無効化する

策定日: 2026-09-05
対象ブランチ: `feature/winforms-ime-optout`
ベース commit: main `e740067`(PR #71 = 設定ダイアログ寸法修正のマージ後)
設計書: `2026-09-05-winforms-ime-inference-optout-design.md` / 実装計画: 同名(`-design` なし)

**このブランチの L5 は必須**(設計書 §7)。本対策の目的そのものが「スクリーンリーダーが
何を読み上げるか」を変えることであり、CLAUDE.md §5 の「App の Speech 系に触れる変更は必須」に
直接該当する。しかも本件は**発声を減らす**変更なので、**減らしすぎていないこと**(半角/全角の
正当なフィードバック・日本語入力中の読み上げ)の確認も同じ重みで要る。

**未実施。** 判定欄は空にしてある。実施時に **PASS / FAIL / N/A** を記入し、FAIL は
**聞こえた文言を逐語で**残す(要約しない)。

> ## ⚠ 手順の順序を守らないと、全項目が偽の PASS になる
>
> この発声は **`Control.s_propagatingImeMode` が武装しているときだけ**起きる。武装するのは
> **ユーザーが IME を切り替えたとき**で、**1 回発火すると `Inherit` に戻り、次に IME を
> 切り替えるまで再武装しない**(設計 §2.2)。
>
> つまり **「半角/全角を押す → 対象操作をする」の順でなければ、修正前のビルドでも鳴らない。**
> 順序を守らずに「鳴らなかった」を PASS と書くと、**直っていなくても全項目が緑になる。**
>
> - 対象操作の**直前**に半角/全角を押す(タブを開く等の下準備は**先に**済ませておく)。
> - **同じ項目を続けて 2 回撃つときは、毎回押し直す。**
> - 各項目は **3 回以上**繰り返す(設計 §3.1 の実測は各 5 回)。1 回だけ静かでも根拠にならない。

> ### ★ 自動テストは「実際に効いたか」を原理的に固定できない —— 回収点は本書だけである
>
> 設計 §7 の追記のとおり、`Main` の配線は IL 走査(`IlCallees`)で**呼び出しの有無と
> IL 上の出現順**まで固定してある。だが固定できないものが残る(いずれも実測):
>
> - **実行順ではない。** 固定できるのは IL 上の出現順までで、**呼び出しを条件分岐に入れる変異**
>   (`Environment.TickCount < 0 ? … : default`)は IL 上に現れるため**生存する**。
> - **渡した引数の値**は呼出集合では観測できない(オーバーロードの弁別は引数の個数で守れている)。
> - **推測抑止が実際に効いて発声が消えたか**は、`ImeStartupTests`(テーブルが塗られたことの観測)
>   でも届かない。塗ったことと、SR が黙ることは別の主張である。
>
> したがって **「起動時に実際に呼ばれて、実際に効いたか」の最終確認は L5(項目 8 / 項目 9)が
> 唯一の回収点**である。ここを飛ばすと、この変更は「効いているはず」以上の根拠を持たない。

### 0.2 何と比較して「出ない」なのか(弁別の基準)

期待が「出ない」の項目(1 / 2 / 3 / 7)は、**修正前に鳴っていたもの**が消えることを見る。
修正前の実測は設計 §3.1(各シナリオ 5 回・数値 = `IMN_SETOPENSTATUS` の発生回数):

| シナリオ | 修正前 | 対策後(ハーネス実測) |
|---|---|---|
| タブを閉じる・IME OFF(通常状態) | **10**(= 毎回 2 回)`[2,2,2,2,2]` | 0 `[0,0,0,0,0]` |
| タブを閉じる・IME ON(入力中) | 5(= 毎回 1 回)`[1,1,1,1,1]` | 0 |
| 設定ダイアログ(閉じる)・IME OFF | **10**(= 毎回 2 回)`[2,2,2,2,2]` | 0 |
| 設定ダイアログ・IME ON | 0 | 0 |
| `ImeMode.Disable` 欄の往復(行へ移動) | **10**(= 毎回 2 回)`[2,2,2,2,2]` | 0 |

  ここが修正前に **2 回**鳴っていた系列で、弁別が最も明瞭である。
- **IME ON のまま撃つと、修正前でも設定ダイアログは 0 回**である(上表)。
  ON の系列だけで「鳴らない」を確認しても弁別にならない。

## 1. 発声が消えること(本対策の目的)

**共通の前提操作**: 対象操作の**直前**に **半角/全角 を押して IME を ON にし、もう一度押して OFF に
戻す**(= 直前に切り替えた状態 = 武装済み・`PropagatingImeMode` が `Off`)。
このとき NVDA が「日本語変換」→「変換停止」と読むのは**正しい**(項目 4 で確認するもの)。
**その後の操作**で追加の「文字変換」「変換停止」が出るかどうかを見る。

| # | 前提操作 | 手順 | 期待 | 判定 |
|---|---|---|---|---|
| 1 | タブを 2 枚以上開いておく(`Ctrl+N` または `a.txt` / `b.txt` を開く)。**その後**半角/全角で ON→OFF | `Ctrl+W` でタブを閉じ、残ったタブへフォーカスが移るまで聞く | タブ名(またはファイル名)は読まれるが、**「文字変換」「変換停止」が出ない**。修正前はここで必ず 2 回鳴っていた(§0.2) | |
| 2 | 半角/全角で ON→OFF | `Alt` → `O`(オプション)→ `P`(設定)で設定ダイアログを**開く** | **出るかどうかを記録する**(設計 §2.2 の未確定点。ハーネスでは開くときの再現が採れていない = 0/5)。対策後の期待は「出ない」だが、**出た場合も FAIL ではなく実測として記録**し、逐語を残す | |
| 3 | 項目 2 の続き(ダイアログを開いたまま。**閉じる直前にもう一度**半角/全角で ON→OFF する) | `Esc` でダイアログを**閉じる**。編集領域へ戻るまで聞く | **「文字変換」「変換停止」が出ない**。修正前はここで必ず 2 回鳴っていた(§0.2)。モーダルなので `WmImeKillFocus` の第 1 項が成立する経路である | |

> 項目 3 の前提操作を忘れやすい。項目 2 で 1 回発火していれば武装は解けている
> (発火していなくても、開いた時点の他のフォーカス移動で解けうる)。**閉じる直前に押し直す。**

## 3. 残存の確認(設計 §6.2 の受容事項 —— **不具合ではない**)

`GoToLineDialog` / `CsvGoToCellDialog` の入力欄は `ImeMode = ImeMode.Disable` を設定している。
これは **kxEdit 側からの IME 制御**で、本ブランチでは**撤去しない**(ユーザー判断)。
その結果、**日本語入力中にこれらのダイアログを使うと、戻っても IME が切れたままになる**。

- 修正前は WinForms の推測機構が「復元役」を兼ねていて気づかなかった。本対策はその復元役も止める。
- **したがって、下の 2 項目は「そのとおりなら PASS」**である。発声が出ること・IME が切れたままに
  なることを**確認して記録する**のが目的で、直す対象ではない。
- 撤去する場合の手順は設計 §6.2 の申し送り: **`ImeMode.Disable` → `NoControl` に変え、全角数字は
  入力値の正規化(全角→半角に変換してからパース)で担保する**(`GoToLineDialog.cs` /
  `CsvGoToCellDialog.cs` の 2 ファイル + 正規化 1 箇所)。撤去の判断材料として、
  **戻ったときの体感がどれだけ困るか**を実施記録に一言残すこと。

| # | 手順 | 期待(= 受容事項どおり) | 判定 |
|---|---|---|---|
| 6 | 通常モードで**日本語入力を ON にしたまま**(未確定文字列は確定しておく)`Ctrl+G`(行へ移動)を開く → `Esc` で閉じる → 編集領域で日本語を打ってみる | ダイアログの入力欄へ入った時点で **IME が閉じる(発声あり)**。**戻っても IME は切れたまま**で、そのまま打つと半角英数が入る。半角/全角を押せば元に戻る | |
| 10 | CSV モードで**日本語入力を ON にしたまま** `G`(または `Ctrl+G`)で「セルへ移動」を開く → `Esc` で閉じる → セル上で日本語を打ってみる(F2) | 項目 6 と**同じ残存**が出る(`CsvGoToCellDialog` も `ImeMode.Disable`)。項目 6 と挙動が違うなら、その差を逐語で記録する | |

## 4. 無効化が実際に効いたことの確認(★ §0.1 の唯一の回収点)

| # | 手順 | 期待 | 判定 |
|---|---|---|---|
| 8 | 起動時の `Trace` を観測する(下の観測手段を参照) | 成功時: `kxEdit ime: WinForms ImeMode inference disabled (...)` が 1 行出て、括弧内に `s_japaneseTable` / `s_koreanTable` / `s_chineseTable` の **3 つが並ぶ**(**順序は不定** —— `Type.GetFields` の返却順は仕様上未定義。並び順で FAIL を付けないこと)。失敗時は `kxEdit ime: WinForms ImeMode inference NOT disabled: <理由> (patched so far: ...)` が**警告**として出る。**観測できた行を逐語で記録する** | |
| 9 | **弁別の実測**(任意だが強く推奨): 修正前のビルド(main `e740067` を別ディレクトリでビルド)で項目 1 を同じ手順で撃つ | 修正前は **1 回の `Ctrl+W` につき「文字変換」「変換停止」の 2 発声**が出る。本ブランチでは出ない = **弁別できている**。撃たない場合は「未実施(弁別は §0.2 の過去実測に依拠)」と書く | |

**項目 8 の観測手段**(いずれも取れなければ **「観測せず」と正直に書く**。観測できないものを PASS にしない):

1. **Visual Studio / VS Code で `kxEdit.App` をデバッグ起動**し、**出力ウィンドウ**の
   デバッグ出力を見る。`Trace.TraceInformation` は既定リスナ経由で
   デバッガーに届く(`Markdig=` の行も同じ場所に出るので、**それが見えていれば観測面は生きている**)。
2. **DebugView(Sysinternals)**で `OutputDebugString` を拾う。ただし .NET 9 の
   `DefaultTraceListener` は `Debugger.Log` 経由のため**拾えない可能性がある**。
   1 行も出ないときは「DebugView では観測できなかった」と書き、**「効いていない」と読み替えない**
   (項目 1 / 3 の結果と混同しないこと)。
3. どちらも取れないなら **N/A(観測手段なし)**。そのとき本対策が効いた根拠は
   **項目 1 / 3 の実発声だけ**になる —— その旨を実施記録に明記する。

> **項目 8 が失敗行(`NOT disabled`)だった場合は FAIL**。.NET の更新で内部構造が変わって
> テーブルを発見できていない(設計 §6.3)。この場合、項目 1 / 3 も鳴るはずである
> ——**鳴らないのに `NOT disabled` なら、鳴らない理由が別にある**(武装し忘れ = 偽 PASS)ので、
> §0 の順序から撃ち直すこと。

## 5. 判定

- **項目 1 または 3 が FAIL(鳴る)なら、本対策は届いていない。** マージしない。
- **項目 4 または 5 が FAIL(黙る / 入力できない)なら、潰しすぎである。** マージしない
  (発声を減らす変更で、正当なフィードバックまで消すのは退行)。
- **項目 2 は「出るかどうかの記録」項目**。出ても FAIL ではないが、**出た事実は設計 §2.2 の
  未確定点への回答**なので必ず逐語で残す(次に触る人の一次資料になる)。
- **項目 6 / 10 は「残存の確認」項目**。期待どおり残っていれば PASS。**残っていない場合も
  FAIL ではなく記録**(WinForms 側の挙動が想定と違うことになるので、逐語と再現手順を残す)。
- **項目 7 が FAIL(追加の発声が出る)なら、CSV の F2 経路に別の供給源がある。** 記録して報告する。
- **項目 8 が観測できなければ N/A。PASS にしない。**
- **どの項目も、§0 の前提操作(半角/全角の押し直し)を守れていない試行は無効。**
  静かだったことは、順序を守っていない限り何の根拠にもならない。

## 7. L5 項目にしなかったものと、その理由

| 対象 | 理由 |
|---|---|
| **`ImeMode.Hiragana` 等を明示設定したコントロールの読み値退化**(設計 §6.1) | kxEdit に該当コントロールが**ゼロ**(`ImeMode.Disable` ×2 と `NoControl` ×1 のみ)。実機で観測する対象が存在しない。将来足したときは L3 `ImeStartupTests` が先に気づく |
| **韓国語 / 中国語 IME での確認** | 塗る対象に含めてはいるが(`s_koreanTable` / `s_chineseTable`)、kxEdit の想定ユーザー環境ではない。項目 8 のログでテーブル名が出ていることをもって足りるとする |
| **「毎回ではなく、することがある」の再現率** | 再武装の仕様(§0)から説明が付いており、順序を守れば決定的に再現する。確率の測定は L5 の仕事ではない |
| **`.NET` 更新後の追従** | 設計 §6.3。壊れても no-op に落ちる(症状が戻るだけ)。CI の `ImeStartupTests` が検知する |
