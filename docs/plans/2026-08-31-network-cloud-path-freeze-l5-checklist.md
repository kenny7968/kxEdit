# L5(実機 SR 検証)チェックリスト — ネットワーク/クラウドのパス喪失と UI 凍結

対象ブランチ: `feature/network-cloud-path-freeze`(A-15 / A-16 / A-17)
設計書: `2026-08-31-network-cloud-path-freeze-design.md` / 実装計画: 同名(`-design` なし)

**このブランチの L5 は、`l5-backlog-after-v02-audit` の未消化分とは別に必ず実施する。**
SR 経路(復元時の発声・grep 通知)に触れる変更を含むため(CLAUDE.md §5)。

## 0. なぜ L5 が必要か(自動テストで届かない範囲)

実装中に**自動テストでは原理的に届かない**ことが 3 つ確定した。ここが L5 の存在理由。

| 未確認 | なぜ自動テストで届かないか |
|---|---|
| 実クラウドプレースホルダーでの `Check` = Ok | 開発機に Files On-Demand の実体を作れない(`%OneDrive%` の同期実体が空)。網は合成タグ `0x00000123` と Microsoft の `0x9000001A` を植えたものだけ |
| `FILE_FLAG_OPEN_REPARSE_POINT` が hydrate を誘発しないこと | 同上。cldflt 管理下の実プレースホルダーが要る |
| `DriveType=Network` のままサーバー不達での凍結解消 | ネットワークマッピングの作成が要る(エージェントの環境ガードレールで禁止) |

**重要な切り分け(Task 5 のレビューが実測)**: 凍結が実際に起きるのは 2 つだけ。

- **(a) 到達不能な UNC 直指定** — `Directory.Exists(@"\\<不達ホスト>\share\nosuch")` が **21,002 ms** ブロック(実測)。
- **(b) `DriveType=Network` のままサーバー不達** — 未実測。**本チェックリストの項目 2 が唯一の観測面。**

**切断済み(reconnect 待ち)のマップドドライブは対象外**。`DriveInfo(@"W:\").DriveType` が
`NoRootDirectory` を返すので `RemotePathDetector.IsRemote` が false になり、
`Directory.Exists` も 2 ms で返る(実測)。**この状態で「凍結しない」ことを確認しても
何も検証したことにならない**ので注意。

## 1. 実施手順のノウハウ(前回までに確立済み)

- windows-mcp の `Snapshot` は `use_ui_tree=true` で応答が返らないことがある(1800 秒無応答)。
  **`use_ui_tree=false` + スクリーンショットの座標読み**で完走できる。
- `Type` ツールは**バックスラッシュを取りこぼす**。UNC パスの入力は `Clipboard` set → Ctrl+V。
  投入後に必ず画面で確認する。
- kxEdit は**コマンドライン引数を受け取らない**。Ctrl+O 直後の `Type` は、ダイアログの出現を
  スクリーンショットで確認してから打つ(確認せず打つと本文へ流し込む事故が起きる)。
- **実発声は NVDA スピーチビューアーで逐語確認する**(手法は `save-encoding-loss-warning` で確立)。
  「ダイアログが出た」ではなく「**何と読み上げたか**」を記録すること。
- Alt+M 直後のキー送出は本文に入る(メニュー展開を Wait してから送る)。

## 2. 事前準備

1. Release ビルドの kxEdit を用意する(`dotnet build kxEdit.sln -c Release`)。
2. NVDA を起動し、スピーチビューアーを開く。
3. **項目 1 用**: OneDrive にファイルを同期し、Files On-Demand を有効にする。
   「空き領域を増やす」で dehydrate した状態と、「このデバイス上に常に保持する」で
   hydrate した状態の**両方**を作る。
4. **項目 2 用**: 到達可能な共有へドライブをマップし、**マッピングを生かしたままサーバーを
   不達にする**(共有側を落とす / ネットワークを切る)。切断済みで `NoRootDirectory` に
   落ちた状態では検証にならない(§0 参照)。
   マップドドライブを用意できない場合は、**UNC 直指定**で (a) の経路だけでも確認する。

## 3. チェック項目

### 項目 1 — A-15: クラウドプレースホルダーが無題に降格しないこと ★本命

| # | 操作 | 期待 |
|---|------|------|
| 1-1 | OneDrive 配下の **dehydrated** な .txt を開く | 開ける。ダウンロードが走る(これは正常) |
| 1-2 | 編集して hot exit(バックアップ ON・保存せず終了) | — |
| 1-3 | 再起動して復元 | **パス付きで復元される**。タイトル/タブが「無題」に**なっていない** |
| 1-4 | 復元時の発声を逐語記録 | 「元パスが無効」「到達できませんでした」の**どちらも出ない** |
| 1-5 | 1-1〜1-4 を **hydrated**(常に保持)なファイルで繰り返す | 同上 |
| 1-6 | OneDrive 配下の**フォルダー**の下にあるファイルで繰り返す | 同上(フォルダー単位のプレースホルダーが本命の形) |

**同時に実測して設計書 §2.2 へ追記すること**:
- dehydrated / hydrated それぞれの `File.GetAttributes` の値(`ReparsePoint` が立つか)
- reparse タグの値(`0x9000001A` 系か)
- **1-1 の前に `TryRead` 相当が hydrate を誘発しないこと**。dehydrated のまま復元 → 一覧で
  「オンラインのみ」アイコンが維持されているか、ダウンロード通知が出ないかで観測する。

### 項目 2 — A-16: マップドドライブ不達で凍結しないこと

| # | 操作 | 期待 |
|---|------|------|
| 2-1 | 不達のマップドドライブ上のファイルを開いた状態で hot exit | — |
| 2-2 | サーバー不達のまま起動して復元 | **UI が長時間凍結しない**(5 秒 × レコード数の範囲) |
| 2-3 | 復元ダイアログの発声を逐語記録 | 「バックアップの元パスに**到達できませんでした(5 秒)。ネットワーク接続を確認してください**。無題タブとして復元します。」 |
| 2-4 | 2-3 の文言が「元パスが**無効**なため」に**なっていない**こと | 不達を「無効」と説明しない(Task 6 fixup) |
| 2-5 | 復元後、本文が失われていないこと | 無題タブとして本文は保持される |

**2-2 では `RemotePathDetector` 自体がブロックしないことも観測する**(設計書 §10.4)。
`DriveInfo.DriveType` が不達のマップドドライブでブロックするかは**未実測**で、
もしブロックしていれば**ここで凍結が残る形で現れる**。

### 項目 3 — A-17: grep が不達フォルダーで固まらないこと

| # | 操作 | 期待 |
|---|------|------|
| 3-1 | grep で不達の UNC(`\\<不達ホスト>\share`)を指定して実行 | **約 5 秒**で打ち切られる(21 秒待たない) |
| 3-2 | 3-1 の発声を逐語記録 | 「フォルダが見つかりません」 |
| 3-3 | 同じ状態で「参照」ボタンを押す | ダイアログが**開く**(固まらない)。初期選択が無いだけ |
| 3-4 | 到達可能なリモートフォルダーで grep | 従来どおり検索が走る(5 秒で誤って打ち切らない) |

### 項目 5 — symlink の拒否(条件付き)

自動テストでは symlink を作れなかった(`SeCreateSymbolicLinkPrivilege` が無く win32=1314)。
**管理者権限または開発者モードが使える場合のみ**実施する。

| # | 操作 | 期待 |
|---|------|------|
| 5-1 | BlockedRoot(`C:\Windows\System32\...`)を指す symlink を作り、その経路のパスを復元させる | **無題に降格**(Rejected) |

実施できない場合は「未実施」と記録し、根拠がタグ分類(`0xA000000C & 0x20000000 ≠ 0`)の
論証のみであることを申し送りに残す。
